# DesignAI Web — локальный dev-инструмент генерации веб-дизайна

Локальное веб-приложение для работы с Design IR: генерация вариантов UI через LLM,
живое превью, ручное редактирование, правки через промпт и детерминированный микс
вариантов по весам.

## Запуск

```bash
.venv/Scripts/python app/server.py
```

Открывается `http://127.0.0.1:8420` (браузер открывается автоматически).
Зависимости уже стоят в `.venv` (fastapi, uvicorn, jsonschema). При чистой установке:
`python -m venv .venv && .venv/Scripts/python -m pip install fastapi uvicorn jsonschema`.

## Архитектура

```
app/
  server.py            FastAPI + uvicorn, порт 8420. Импортирует spike/run_test.py
                       как модуль (chat / build_system_prompt / extract_json) — код LLM-клиента не дублируется.
  colorutils.py        sRGB ↔ OKLab/OKLCH конвертация (формулы Ottosson) и взвешенный
                       микс hex-цветов. Только stdlib.
  static/
    index.html         одна страница-полотно, три зоны, тёмная тема (#5B5BD6, Inter).
    app.js             состояние вариантов, инспектор, редактирование, история, микс, toasts.
    renderer.js        Design IR → DOM: генерирует <style> с CSS-переменными из tokens,
                       Google Fonts, классы компонентов; масштабирование превью под колонку
                       (дизайн-ширина 960px, transform scale).
```

Эндпоинты (все LLM-вызовы — через `spike/run_test.py`, провайдер по умолчанию `qwen`):

| Метод | Что делает |
|---|---|
| `POST /api/generate` | `{brief, count, provider, styleHint?, seedTag?}` → `{variants, errors}`. count параллельных вызовов LLM (ThreadPoolExecutor), в user-промпт каждого добавляется «вариант N: визуально отличное решение №N». Температура qwen 0.8 (kimi принудительно 1 — это делает сам run_test). Варианты, упавшие поодиночке, не роняют остальные — возвращаются в `errors`. |
| `POST /api/analyze-header` | Читает `test-targets/rsale-site/header-extracted.html` + фрагменты `page-ru.html` (стили + начало, чтобы уложиться в контекст), LLM возвращает `{structureSummary, suggestedTokens, headerBrief}`. Кэш в `test-targets/rsale-site/analysis.json`; `force=true` обходит кэш. |
| `POST /api/mix` | `{irs, weights}` → `{ir}`. Детерминированно: цвета — взвешенная интерполяция в OKLCH (hue по кратчайшей дуге, веса нормализуются; все нули → равные доли), enum-токены (font family, radius, mode, spacing, shadow) и всё `tree` — от варианта с максимальным весом. Пишется `meta.mixOf: [{index, weight}]`. |
| `POST /api/refine` | `{ir, instruction, provider}` → `{ir}`. LLM получает текущий IR + инструкцию, возвращает полный обновлённый IR. Ответ валидируется по схеме; при невалидности — один repair-вызов со списком ошибок; если и он невалиден — 502. |
| `POST /api/validate` | `{ir}` → `{ok, errors[]}` (jsonschema Draft-07 по `schema/design-ir.schema.json`). |
| `GET /` + `/static/*` | фронтенд. |

**Изменение схемы:** в `schema/design-ir.schema.json` в `meta` добавлено необязательное
свойство `mixOf` — без него результат `/api/mix` не проходил валидацию
(`additionalProperties: false`). Изменение обратно совместимо: все существующие
IR из `results/` валидны по-прежнему (проверено `spike/validate.py`).

## Как работает редактирование и возврат в промпт

- **Текст.** В режиме «Редактировать» клик по текстовому элементу превью делает его
  contenteditable. Рендерер проставляет каждому редактируемому узлу `data-ir-path`
  (например `props.links.0.label`, `props.cta.text`, `props.heading`, `props.tiers.1.features.2`)
  и `data-ir-sec` (индекс секции) — после blur новое значение пишется точно в
  `ir.tree[sec]` по этому пути, превью перерендеривается.
- **Токены (инспектор справа).** Color-picker на каждый из 8 цветов, селекты шрифтов
  (8 Google Fonts), плотность типографики, пресет радиусов, отступы секций, тени,
  тумблер light/dark (инверсия яркости нейтральных токенов по luma; primary/accent
  не трогает). Все изменения мгновенно применяются к превью и живут прямо в IR.
- **«Отправить в промпт» (refine).** Текущий IR (со всеми ручными правками) +
  текстовая инструкция уходят в `/api/refine`; модель возвращает обновлённый IR,
  который заменяет вариант. Предыдущая версия пушится в историю карточки, кнопка
  «← назад» откатывает. Так ручные правки и промпт-правки комбинируются: модель
  видит уже отредактированные токены/тексты как факт.
- **Веса и микс.** У каждой карточки слайдер 0–100% (по умолчанию 100/33/0…).
  «Смешать по весам» отправляет все IR и веса/100 в `/api/mix`: цвета интерполируются
  в OKLCH пропорционально весам, а структура страницы, шрифты, радиусы и режим — от
  варианта с максимальным весом. Результат добавляется новой карточкой справа с
  пометкой «Микс (#1:60% + #2:40%)» и `meta.mixOf` внутри IR.

## Найденные баги и исправления

1. **Микс не проходил валидацию** — `meta.mixOf` запрещён схемой (`additionalProperties:false`).
   Исправлено расширением схемы (необязательный `meta.mixOf`), обратная совместимость
   подтверждена на `results/b1-qwen-t07.json`.
2. **Конфликт `data-ir-path` между секциями** — одинаковые пути (`props.heading`) в разных
   секциях могли записать текст не в ту. Исправлено: рендерер помечает корень секции
   `data-ir-sec`, запись идёт в конкретную секцию.
3. **Падение микса на частичном IR** (нет `tokens.color` у доминанта) — добавлены гарды.
4. **Падение рендерера на IR с неполными tokens** — добавлены дефолтные токены (merge).
5. **Бесконечный цикл MutationObserver** в инспекторе — убран, счётчик истории обновляется явно.
6. **Спам `/api/validate`** при драге color-picker — дебаунс 400 мс.

## Ограничения / что не работает

- **Радиусы в инспекторе — один пресет** на card/button/input (по схеме они раздельные).
- **Light/dark toggle** — простая инверсия luma нейтральных цветов, а не полноценная
  перегенерация палитры; для качественной смены темы лучше refine «переведи в тёмную тему».
- **Превью — десктопная раскладка 960px**, масштабируется transform'ом; мобильные
  варианты блоков не рендерятся, hover/интерактив (аккордеон faq, карусели) статичны.
- **`suggestedTokens` из анализа** может содержать ключи вне схемы (модель добавляет
  `primaryHover` и т.п.) — на свотчи и бриф не влияет, в `/api/mix` не идёт.
- **contenteditable работает только с текстовыми пропсами**, размеченными рендерером;
  тексты внутри произвольных `children`-элементов card-структур редактируются, но
  сложные вложенные случаи могут не иметь data-ir-path.
- **Валидация чипа** показывает только первые 5 ошибок (tooltip).
- Генерация не валидирует ответ модели по схеме на бэкенде — невалидный вариант попадёт
  на полотно и будет помечен красным чипом (это осознанное решение: видеть и чинить, а не терять).
- При старте сервер открывает вкладку браузера — при перезапусках копятся вкладки.
