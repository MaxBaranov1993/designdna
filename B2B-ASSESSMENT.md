## 1. Как я понимаю проект (одним абзацем)

DesignAI Web — **нодовый редактор веб-дизайна с LLM-генерацией**: граф как в
ComfyUI/Houdini, инструменты правки как в Figma. Ключевое техническое отличие от
v0 / Claude Design / Figma Make: модель генерирует **не картинку и не код**, а
**Design IR** — редактируемый JSON (дизайн-токены + дерево секций из закрытой
библиотеки ~19–25 блоков). Генерация, микс вариантов по весам, ручная Figma-правка
и возврат правок в промпт — всё это операции над одним IR. Консистентность
гарантируется архитектурно (закрытый каталог блоков + токены), а не «надеждой на модель».

Позиционирование из документов: конкурент v0/Claude Design **с ручным управлением** —
для тех, кому нужен контроль над результатом, а не лотерея.

## 3. Для кого

Зафиксировано в AGENTS.md (решение владельца от 2026-08-04):

- **Первый платящий пользователь — дизайнеры и студии.** Редактор, варианты, микс,
  дизайн-док — первичны; экспорт кода вторичен.
- Вертикаль из PLAN.md: **лендинги (SaaS/продукты)** — самый предсказуемый сегмент,
  блочная структура идеально ложится на IR.
- Потенциально также: агентства (поточное производство однотипных страниц),
  фрилансеры, продуктовые команды без дизайнера.

Внутренний конфликт сегментации, который я вижу: нодовый UX (ComfyUI) — язык
AI-инженеров и техлидов, а «дизайнеры/студии» мыслят холстом и библиотеками.
Это главный продуктовый вопрос (см. вопросы ниже).

## 4. Как работает (основной цикл)

```
Задача («сделай шапку», «карточка объявления»)
  → Генератор: LLM выдаёт N вариантов IR (не картинки), провайдер/модель на выбор
  → Микс: 2–4 IR + слайдеры весов; цвета — взвешенная интерполяция в OKLCH,
    структура — от варианта-доминанта (детерминированно, без LLM)
  → Figma-правка прямо в ноде/полноэкранном редакторе: drag (snap 8px), resize,
    тексты inline, токены через инспектор, слои, группировка, Z-order
  → refine: отредактированный IR + инструкция → LLM → следующая итерация
    («продолжить от этой версии»)
  → Новые компоненты на той же стилевой ДНК → дизайн-док → UI/UX-система (Фаза 4, ❌)
```

Дополнительные пайплайны:

- **Клонирование с сайта** (`/api/clone`): URL + «какой компонент» → IR точь-в-точь.
- **Pixel-perfect reproduction** (скриншот → HTML с pixel diff < 5%): VLM даёт только
  структуру, все числа (цвета, bbox, радиусы) измеряются Python-скриптами из пикселей;
  достигнутый результат: 4.7% diff на реальном сайте (RSale header).
- **Vision-декомпозиция** скриншота в компоненты (4 провайдера с fallback-цепочкой).

## 5. Зрелость: факты

**Есть:** работающий end-to-end цикл в нодовом графе; валидированное ядро (spike GO);
Figma-ядро уровня «drag/resize/guides/group/lock/undo»; кэш и cost-aware роутинг
моделей; SSRF-защита; документация и тесты; отлаженный агентный процесс разработки.

**Нет (критично для SaaS):** аутентификация, проекты/команды, хранение в БД
(сейчас localStorage), биллинг/квоты, экспорт результата (HTML/React/Figma),
дизайн-док/Style DNA, RAG, мобильные расклады (превью только 960px), деплой/мониторинг.

**Задекларированный техдолг** (AGENTS.md): потеря данных в localStorage,
дубликат renderer.js в gallery, CSS-инъекции (частично закрыто тестами), миграция
фронта на React Flow не начата фактически (ветки flow-spec/flow-scaffold на HEAD).

## 6. Оценка как B2B SaaS

### Сильные стороны

1. **Технический moat.** IR + закрытая библиотека + детерминированный микс —
   не копируется за неделю; конкуренты про «промпт → картинка» этого не дают.
2. **Контроль как ценность.** B2B-студиям нужна воспроизводимость и итеративность,
   а не лотерея — позиционирование честное и дифференцированное.
3. **Ядро проверено.** 42 генерации, repair 100%, 20 тестов API, Playwright-тесты UI —
   решение go/no-go принято на данных, а не на вере.
4. **Экономика продумывается.** Роутинг дешёвых/дорогих моделей по ролям,
   sqlite-кэш повторов, план «токен-бюджет как фича».
5. **Зрелый процесс.** Документация, код-ревью, мульти-агентный пайплайн с
   ревью — редкость для прототипа.

### Слабые стороны и риски

1. **Разрыв «локальный инструмент → SaaS».** Нет auth/команд/биллинга/БД/деплоя.
   Фаза 5 оценена в 2–3 недели, но для B2B (SSO, роли, безопасность, аптайм) — дольше.
2. **Нодовый UX vs целевой сегмент.** Дизайнеры не думают графами. Без «верхнего слоя»
   (мастера/пресеты графов, шаблоны) продукт останется инструментом для гиков.
   Прецеденты: ComfyUI так и не стал массовым для дизайнеров.
3. **Нет артефакта на выходе.** Экспорт (код/Figma) отсутствует даже в зачатке.
   Студия не может «забрать работу и отдать клиенту» → цикл ценности обрывается,
   платить не за что. Для заявленного сегмента это приоритет №1, несмотря на
   решение «экспорт вторичен».
4. **Потолок закрытой библиотеки.** ~19–25 блоков: консистентно, но быстро
   «всё выглядит одинаково». Нужен конвейер расширения библиотеки.
5. **Конкуренция.** v0, Claude Design, Figma Make, Lovable, Bolt — ресурсы и
   дистрибуция несопоставимы. Окно — только в нише «контролируемая генерация
   для профи», и её надо занять быстро.
6. **Юридика Reproduce/clone.** Копирование чужих сайтов 1-в-1 — серая зона;
   в B2B-продажах это всплывёт на первом же security/legal-ревью.
7. **Desktop-only превью (960px).** Для веб-дизайна 2026 responsive — базовое ожидание.
8. **Двойной фронтенд впереди.** Миграция на React Flow при живом legacy —
   самый рискованный участок ближайших спринтов.

### Итоговые баллы (субъективно, 1–10)

| Критерий | Балл | Комментарий |
|---|---|---|
| Технология / ядро | 8 | IR-архитектура, repair, микс, pixel-perfect — сильно |
| Качество исполнения | 7 | Тесты, доки, процесс; минус — vanilla-монолит и localStorage |
| Product-market fit (текущий) | 3.5 | Локальный инструмент; сегмент заявлен, но UX ему противоречит |
| Готовность к B2B SaaS | 3 | Нет auth/биллинга/команд/экспорта/деплоя |
| Рынок / конкуренция | 5 | Рынок горячий, но плотный; ниша «контроль» реальна |
| Монетизационный потенциал | 5 | Кредиты/подписка правдоподобны (аналог Relume), но нужен артефакт |

**Вердикт:** сильный pre-MVP с настоящим техническим дифференциатором. До B2B SaaS —
не «дописать обвязку», а закрыть два продуктовых разрыва: (а) UX для не-инженеров,
(б) артефакт, который клиент уносит. Рекомендация: перед SaaS-обвязкой сделать
вертикальный срез «студия делает лендинг и забирает результат» (экспорт + пресеты
графов), иначе биллинг будет нечего считать.

## 6.1. Решения владельца из диалога 2026-08-05

1. **Сегмент (уточнение решения от 2026-08-04): первично — AI-разработчики и
   соло-фаундеры, технически подкованные.** Вторично: соло-дизайнеры, продуктовые
   команды, студии. Ключевой тезис владельца: «все сейчас используют AI; Figma —
   классический инструмент, не даёт вариативности и быстрого применения
   сгенерированного AI стиля на всех компонентах».
   → Конфликт «ноды vs дизайнеры» снимается выбором сегмента: первичный
   покупатель нодовому UX рад. Фича **Style DNA / распространение стиля на все
   компоненты** становится главным продающим обещанием (в статусе ❌ — приоритет).
2. **UX: ноды остаются как есть** (без мастеров/пресетов на данном этапе).
   Уточнение оценки: product-market fit для первичного сегмента выше, чем
   «дизайнеры/студии»: прецеденты ComfyUI/Replicate показывают лояльность
   технических пользователей к графовым UX. Балл PMF для заявленного сегмента:
   ~5/10 вместо 3.5, при условии быстрого онбординга (шаблоны графов всё же
   желательны как «примеры», не как мастера).
3. **Монетизация: гибрид — подписка + кредиты.** Последствия для архитектуры:
   нужен учёт генераций per-user (кредитный счётчик), тарифные планы с пакетом
   кредитов, видимость стоимости ноды до запуска (есть в PLAN.md как идея
   «токен-бюджет как фича» — становится обязательной для гибридной модели).
4. **Артефакты на выходе: HTML/React-код + дизайн-док/токены** (оба формата).
   Figma-экспорт и публикация страницы — не в приоритете. Последствия:
   экспорт из IR → код становится фичей №1 после ядра; формат дизайн-тока
   (спека токенов + компонентов) хорошо сочетается со Style DNA — оба про
   «системный» результат для команды.
5. **Приоритет ближайших спринтов: миграция на React Flow** (Спринт 5 довести).
   Зафиксированное риск-примечание: миграция откладывает ценность для клиента;
   рекомендуется критерий остановки legacy (паритет фаз A–C из AGENTS.md) и
   параллельная работа над экспортом сразу после переключения `/` на новый UI.
6. **Reproduce: только «свои» сайты.** Позиционирование — перенос собственного
   стиля/легаси между проектами; в ToS SaaS-версии нужен явный запрет
   клонирования чужих сайтов. Это снимает главный юридический риск для B2B-продаж.
7. **Монетизация: гибрид — подписка + кредиты.** Последствия для архитектуры:
   нужен учёт генераций per-user (кредитный счётчик), тарифные планы с пакетом
   кредитов, видимость стоимости ноды до запуска (есть в PLAN.md как идея
   «токен-бюджет как фича» — становится обязательной для гибридной модели).

## 7. Вопросы и их статус (диалог 2026-08-05)

**Отвечены** (решения — в §6.1): сегмент ✅, UX нодов ✅, бизнес-модель ✅,
артефакты ✅, приоритет спринтов ✅, позиция по Reproduce ✅.

**Остались открытыми:**

1. **Горизонт и цель:** первые платящие пользователи или демо для инвестиций?
   Меняет глубину полировки и срок до релиза SaaS-обвязки.
2. **Расширение библиотеки блоков:** кто и как добавляет новые типы секций
   (ручная разработка, LLM-конвейер, запросы пользователей)? Это потолок
   разнообразия результатов.
3. **Онбординг без мастеров:** раз ноды остаются как есть — достаточно ли
   библиотеки шаблонов графов (примеры «открой и повтори») для удержания
   вторичных сегментов (дизайнеры, команды)?
4. **Ценовые ориентиры:** с чем сравниваем себя по цене (Relume $16–48/мес,
   Framer, v0 $20/мес)? От этого зависит размер пакета кредитов.
5. **Бенчмарк качества:** PLAN.md предлагает 50 эталонных брифов — заводить
   сейчас (до SaaS) или после миграции фронта?
