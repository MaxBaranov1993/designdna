# Ноды, листы и выполнение задач

Политика фонового выполнения обновлена и проверена в упакованном Electron 2026-09-10.
Итоги: [проверка независимых операций](async-node-execution-status-2026-09-10.md).
Исторические результаты проверки 2026-09-07 сохранены ниже.

## Границы состояния

- `FlowStoreState.nodes/edges` — граф активного листа. `pages` хранит снимки остальных листов; перед переключением активный граф сохраняется в свой снимок.
- Числовой ID ноды локален листу. Сам по себе ID не идентифицирует результат асинхронной задачи.
- `captureNodeScope` связывает продолжения с листом, поколением графа и временем жизни ноды. `bindPageState` и `page-state.ts` привязывают действия и вложенные вызовы к исходному листу; запись в скрытый лист не переключает видимый граф.
- Переключение и создание листа не отменяют задачи. Удаление ноды/листа и явная замена графа инвалидируют только затронутую работу. Проверки входов, точной ревизии Source/DS и master hashes сохраняются.
- Контроллеры, серверные run ID, загрузки файлов и таймеры используют пару `(pageId, nodeId)`. Прогресс, busy, журнал и undo хранятся отдельно для каждого листа в `pageRuntimes`; runtime-поля не входят в сейв. Результаты скрытых листов сохраняются обычным CAS-автосейвом.
- Перед запуском и сменой листа завершаются отложенные текстовые правки. Возврат восстанавливает состояние задач и сохранённый viewport; отложенный auto-fit не меняет другую страницу.
- Список «Задачи» объединяет запуски всех листов. Отмена адресована исходной ноде без навигации; переход по строке открывает её лист и выделяет ноду.
- Снимок канваса передаёт ID своего листа. Устаревшая геометрия/выделение не применяется к другому листу.
- Межлистовой обмен данными выполняется через явные каналы/Page Bridge. Обычный провод связывает ноды текущего графа.

## История и изображения (2026-09-13)

Структурный Undo/Redo восстанавливает состав графа и геометрию, сохраняя свежие
`data` существующих нод. Удалённая нода восстанавливается со своим снимком.
Изменение динамических портов явно отмечает `inputs` как часть операции истории;
после восстановления входы пересчитываются по актуальным источникам.

Успешный apply картинки публикуется до проверки ресурсов. Сетевой сбой reconcile
не переводит готовые слоты в failed: проверка повторяется автоматически один раз,
затем её ошибка сохраняется отдельно как `verificationError`. В истории доступен
повтор проверки; уже готовые изображения повторно через AI не создаются.
Отмена после apply сохраняет опубликованные картинки и не применяет поздний ответ.
Проверка отмены обработки изображений сравнивает весь IR без зависимости от порядка
ключей JSON и продолжает защищать последующие изменения текста и геометрии.
При загрузке проекта снимки `assetVersions.before/after` проходят ту же миграцию,
что и текущие `ir`, `variants` и `mixVariants`, поэтому Undo работает после
повторного открытия. Source и неизменяемые мастера дизайн-системы не мигрируются
этим путём, включая их историю.

## Очереди и отмена (2026-09-10)

Desktop fetch передаёт каждый AbortSignal в отдельный IPC request ID. `ApiRequestManager`
регистрирует запрос до очереди и отменяет только его: ожидающий запрос не запускается,
активный получает адресный `cancel_token`. Ожидание UI завершается сразу, а рабочий слот
остаётся занятым до фактического завершения кооперативной операции. Отмена и отдельный
таймаут не перезапускают общий Python-процесс. Явный перезапуск движка — отдельное действие.

Сохранения проекта выполняются последовательно. Долгие API-запросы имеют ограниченную
параллельность; статусы и отмена получают отдельный слот того же Python-процесса, где
хранится задание. Source Import выполняет до двух захватов одновременно; его ID создаётся
до постановки в очередь, а `/api/block-parse/job/{id}/cancel` останавливает именно этот
импорт между стадиями и запрещает позднему результату заменить состояние `cancelled`.

Редакторы сохраняют привязку к исходному листу. AI-превью Video остаётся в данных ноды
после закрытия окна и требует явного применения к неизменённому базовому таймлайну.

## Промпт и результаты генератора

`pullInput` читает текущий подключённый промпт; `ownPrompt` используется при отсутствии текста на входе. Подготовка, ответ модели и финализация сохраняют `preparedContextId`; изменение серверной политики/ДС между фазами отвергается сервером.

Генератор сохраняет `generationContext`: ID листа, отпечаток эффективных входов, текст задачи и время начала. Отпечаток учитывает модель/провайдера, параметры, референс и выбор ДС, но не геометрию канваса. Изменение входов во время ожидания останавливает дальнейшее применение ответа.

Оценки прошлого запуска очищаются при запуске и при установке новых вариантов. Quality Pass получает IR и brief именно этого запуска, наследует провайдера, сохраняет отдельные оценки вариантов. Каждому обращению присваивается ID для адресной отмены; отмена не запускает repair/rejudge.

Старые документы без generationContext остаются доступными, но показываются как результат предыдущего запуска. Их оценка не представляется оценкой текущего промпта. Пустые composition/frame-ответы отклоняются до Quality Pass; сохранённый старый пустой ответ объясняется текстом в превью.

## Quality Pass в несколько раундов (2026-09-10)

Судья → починка → повторная оценка повторяются до приёмки: по умолчанию score ≥80, verdict `pass`, отсутствие critical/major и детерминированных дефектов, но не более `max_rounds` (3). Verdict `needs_repair` продолжает цикл даже при высоком балле. Равный балл не считается регрессией; при равных score и количестве critical/major предпочтение получает verdict `pass`.

Каждый раунд перед выбором результата проверяется на сохранение токенов, точных мастеров и требований дизайн-системы, отсутствие новых детерминированных дефектов, падения балла и роста числа critical относительно исходной оценки. Отклонённый раунд останавливает цикл, сохраняет причину в `repair.rounds[]` и не заменяет лучший допустимый IR. Если ранее принятых раундов нет, остаётся исходник. Финальная проверка инвариантов сохраняется дополнительно.

Починка получает полный список замечаний с серьёзностью и путём, цель по баллу, историю прошлых раундов, компактный профиль дизайн-системы и первые экраны desktop/mobile, которые видел судья; её ответ проходит тот же санитайзер, что и генерация. Визуальный кэш хранит индексы первых экранов каждого viewport (`firstScreenIndices`), поэтому нижняя плитка длинной мобильной страницы не подменяет её первый экран. Серверный rejudge рендерит заново и сохраняет эти изображения для следующей починки; desktop повторно использует кэш того же IR. Старый плоский кэш без границ viewport пересоздаётся при подготовке визуальной оценки.

Десктоп: `/api/quality-pass/codex-step` принимает `outputs.judge`, `outputs.repairs[]`, `outputs.rejudges[]` (старые поля `repair`/`rejudge` — первый раунд), `pending.round` нумерует этап. Нода после цикла показывает готовый вариант: статус `ok` при прохождении, `warn` («Готово с замечаниями … · осталось: …») если замечания остались, `err` только когда результата нет.

## Source Import: захват живых страниц не зависает (2026-09-23)

На glebkudr.com (Next.js, бесконечные JS-анимации, аналитические стримы) Precise-импорт молчал 12 минут после desktop-прохода. Причины и защиты в `app/scraper.py`:

- `response.body()` для ответа-картинки, который никогда не заканчивается, блокировал `drain_image_bodies`. Теперь читаются только тела завершённых запросов (`requestfinished`/`requestfailed`), остальные остаются в очереди.
- `locator.screenshot` ждёт «стабильность» элемента и на вечной анимации не уважает таймаут. `_element_png` берёт рамку ограниченным evaluate и снимает `page.screenshot(clip=…)`; резервный путь в `source_capture_pixels` ограничен таймаутами.
- Компилятор и нормализация каруселей идут через `_evaluate_bounded` (CDP `Runtime.evaluate` с `timeout` + гонка с `setTimeout`): runaway-цикл или незавершающийся промис становятся ошибкой блока (`source_capture.compile_failed` в логе), а не зависанием импорта.
- Навигация `_goto_resilient`: 45 с на DOMContentLoaded, при таймауте — `commit` и ожидание DOMContentLoaded без исключения. `scroll_into_view_if_needed` и скриншоты внутри цикла блоков ограничены 3–8 с.

Регрессия: `app/scraper_capture_guard_test.py` (локальный HTTP-сервер со стримом без конца, поздним DOMContentLoaded и анимированным элементом).

## Source Import: снимок страницы и сборка Page как в исходнике (2026-09-23)

Импорт по URL по умолчанию идёт движком `snapshot` (`app/source_snapshot.py`, `SOURCE_CAPTURE_VERSION = "snapshot-v6"`), по образцу html.to.design:

- одна навигация, прокрутка для ленивого контента, активация веб-шрифтов с `font-display: optional`, которые браузер не применил (иначе замеры делаются по запасному шрифту, а IR несёт настоящий, и заголовки обрезаются);
- сегментация по геометрии: спуск через обёртки во всю страницу, `display:contents` раскрывается, секцией считается «полоса» шириной ≥85% родителя; фиксированная шапка — отдельный блок;
- один компилятор на все секции в абсолютном режиме, референсы вырезаются из снимков всей страницы (CDP-клипы после прокрутки);
- на время снимков сеть блокируется внутри Chromium (`Network.setBlockedURLs`) и Python-маршрут SSRF-гарда снимается; перед сменой viewport гард возвращается. Раньше очередь колбэков гарда растягивала закрытие браузера до 97 с.

В `meta` каждого блока: `pageRect` (рамка секции на странице, `source` — URL), `pageRectByViewport`, `pageBackground`. Замеры времени по этапам попадают в `timings_ms` (`captureNavigate`, `snapDesktopReferences` и т. д.). Бенчмарк: `python app/source_fidelity_bench.py <url>` — сходство снимка страницы и рендера IR (slsbmb 0.988, rsale 0.994, glebkudr 0.905; легаси-движок 0.967/0.929/0.814).

Компилятор (`dom-v49`) по разбору glebkudr.com:

- глифы коробки нулевой высоты (`height:0; line-height:0`, стрелка «→» в CTA) выпускаются текстовым слоем по реальной рамке глифов, а не отбрасываются как невидимые;
- `line-height: normal` записывается числом по метрикам шрифта (проба inline-block): без него рендерер наследовал 1.6 и опускал подписи кнопок ниже их рамки;
- `pre`, `pre-wrap`, `break-spaces` сохраняют пробелы (колонки трасс и кода), `pre-line` — переносы;
- чистый 2D-поворот вокруг центра (наклонённые карточки) компилируется в неповёрнутых координатах и воспроизводится `frame.transform`, узел остаётся редактируемым.

Офлайн-рендер (`ir_render`) больше не подменяет встроенным Inter generic-ключевые слова (`ui-monospace`, `system-ui`): на Windows Chromium считал `ui-monospace` именем семейства, и моноширинные блоки рендерились гротеском.

В десктопе Source всегда хранит полноразмерные снимки блобами (`fullResolutionEvidence`); ревью мастеров UI Kit приводит кроп исходника к размеру рендера мастера (`desktop_ai._at_render_scale`). Раньше превью ≤720 px давали кроп в 0.61× и судья отклонял все мастера как «заметно увеличенные». Лишняя неверная операция ремонта мастера (например `gap` у свободной раскладки) отбрасывается, если остаются допустимые.

Прогон glebkudr 2026-09-24 (страница «Test v3»): UI Kit прошёл ревью и опубликовался автоматически. Форма Astra получила оболочку секции (в логе генерации флаг `designSystem.sectionShell`). По результату исправлено:

- `sanitize_font_face_weights` больше не сводит диапазон переменного шрифта «100 900» к «100»: из-за этого все заголовки рисовались самым тонким начертанием;
- рендерер применяет `style` узла к листовым `input`/`textarea`/`select` и `badge`; textarea берёт высоту рамки; поля наследуют шрифт страницы; `padding` рамки листовой кнопки или бейджа идёт внутрь элемента, а не в обёртку, которая сдвигала кнопку;
- `contentGutter` композиции — это отступ контента от края страницы: боковой padding `.sec` (32 px) под ним обнуляется;
- при сборке Page цвет чужой секции, который уже есть в палитре страницы, не переназначается по ролям (синий надзаголовок становился почти чёрным);
- компилятор `dom-v49` вписывает в inline SVG вычисленные fill/stroke потомков: иконки, окрашенные CSS-классами, больше не чернеют.

Нода: desktop снимается всегда; «+ Tablet» и «+ Mobile» добавляются чипами до импорта или кнопками «+ Capture» после (`data.captureViewports`); «AI repair» — отдельный флажок (`data.aiRepair`). Старый `importProfile: 'precise'` читается как все три viewport + AI repair. Ревью мастеров UI Kit пропускает не снятые viewport с причиной `viewport-not-captured`.

Page (`frontend/src/flow/source-layout.ts`, зеркало `app/source_page_layout.py`): блок с `pageRect` становится полосой во всю ширину, закрашенной фоном страницы, с коробкой секции на исходном x; высота полосы — расстояние до следующей полосы того же источника, поэтому зазоры и нахлёсты сохраняются. Чужие секции (Generator, Mix) можно ставить между любыми полосами: они идут потоком и сдвигают следующие, а прозрачный корень такой секции получает фон соседней полосы.

## Проект хранится только в SQLite (2026-09-24)

localStorage-кэш проекта убран. Он переполнялся на больших проектах («localStorage is full — page project saved without large data»), а при старте подменял полный проект урезанной копией: правка во время загрузки 72-мегабайтного проекта отбрасывала проект из базы, и следующий CAS-валидный автосейв перезаписал бы его.

- Автосейв пишет только в SQLite (`serialize.ts`: debounce → idle → вынос картинок в блобы → CAS-POST). До ответа `/api/project/load` холст показывает «Loading project…» и не синхронизируется с базой (`projectHydrated: false`).
- Старый кэш читается один раз: если база пуста, а в localStorage есть проект, он переносится в SQLite, и кэш удаляется только после подтверждённой записи; при загруженном из базы проекте кэш удаляется сразу.
- Если граф изменили во время загрузки, автосейв встаёт на паузу и открывается `ConflictDialog` («The canvas changed while the project was loading»; основная кнопка — загрузить сохранённый проект).
- Выход: окно при закрытии и `before-quit` вызывают `window.__designdnaFlushProject` (`flushProjectToDb`) и ждут записи до остановки Python-воркера (таймауты 30/35 с). `sendBeacon` остаётся только для проектов меньше 60 КБ.
- Page из полос Source: фон сайта (часто градиент `body` на весь документ) пишется в `meta.pageBackground` и рисуется один раз на корне страницы; полосы прозрачны, коробка секции имеет `role: "section"` и рисуется как захвачена (раньше рендерер отбрасывал градиент в `background`, и коробка-`card` получала тень, рамку и отступ сгенерированной карточки: белая страница с тенями вокруг секций).
- Мост десктопа больше не разворачивает `ddna://blobs` в запросах `/api/timeline/*`: таймлайн с копиями страниц хранился с картинками в base64 в каждой ревизии (58 МБ на одну ноду Video). Сохранённые раньше ноды ужимаются один раз после загрузки (`offloadTimelineStories`), автосейв тоже выносит картинки из `story.pages[].ir`. Рендер принимает IR в обоих видах (`timeline_api._same_design_ir`). На рабочем проекте: 86.6 → 14.8 МБ, сохранение 13.4 → 3.1 с.

### Сохранение не может молча удалить страницу

2026-09-24 в рабочем проекте сохранилась версия с одной страницей вместо трёх (страницы восстановлены из резервной копии, причина потери в клиенте не найдена). Теперь `/api/project/save` в CAS-режиме отказывает с 409 `page_loss` (`missingPages`, `missingPageIds`), если сохраняемый проект не содержит страницу из базы, а клиент не назвал её в `deletedPages`. `deletePage` записывает id (`noteDeletedPage`), сохранение передаёт их серверу, после подтверждённой записи список очищается. Диалог конфликта («Saving would remove pages») по умолчанию загружает сохранённый проект; «Remove these pages» — явное удаление. Тесты: `app/project_page_loss_test.py`, `frontend/tests/project-autosave-ordering.test.mjs`.

## Видео: камера и появление секций (2026-09-24)

- Плеер story (`video-story.ts`) переводит вертикаль камеры в прокрутку страницы внутри кадра: раньше камера сдвигала обёртку с кадрами `overflow:hidden`, и после первых секунд ролик был белым.
- Хореография: одна панорама камеры на план (лишние `camera-pan` модели отбрасываются), появление секции начинается до того, как камера приводит её в кадр (`_sync_reveals_with_camera`), пролёт по измеренной странице ограничен скоростью `MAX_PAN_SPEED` (700 px/с), а не 2.5 кадра, чтобы низ страницы (форма, CTA) попадал в ролик.

## Видео: большие data-URL перед рендером (2026-09-22)

`timeline_assets.promote_oversized_data_urls` переписывает `data:`-изображения длиннее `MAX_DATA_URL_CHARS` в контент-адресные блобы `ddna://blobs/<sha256>.<ext>` в глубокой копии IR. Вызывается в `/api/timeline/render`, офлайн-рендере и `ir_render` перед проверкой ассетов, поэтому страницы с встроенными картинками Generator/Image проходят офлайн-гард без ручной подготовки. Маленькие data-URL остаются inline; неразбираемые остаются как есть и отклоняются гардом с прежним сообщением о лимите. Блобы не удаляются автоматически: каталог `<data>/blobs` растёт до ручной очистки.
