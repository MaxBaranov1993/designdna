# План улучшений DesignDNA — скорость, удобство, UI/UX

Составлен по итогам аудита кодовой базы после интеграции работ Claude/Codex (ветка `codex/unified-motion-design`).
Состояние: бэкенд-тесты зелёные, фронтенд собирается без ошибок, QA-цикл rsale.net пройден (design-qa.md).

Приоритеты: **P0** — заметно влияет на каждого пользователя каждый день; **P1** — заметно влияет, но реже или уже частично закрыто; **P2** — качество жизни и технический долг.

- Эффект: главный источник «программа зависла?» исчезает ещё до стриминга.

### 2.2 Стриминг ответов LLM (P1)
- Сейчас: `llm_client.py:243-252` — блокирующий `urllib.request.urlopen`, стриминг явно отвергнут (`:174`). Каждый ответ ждётся целиком.

### 2.3 Инкрементальный рендер артборда (P0 для редактора)
- Сейчас: каждая мутация = `JSON.parse(JSON.stringify(ir))` глубокий клон (`renderer.ts:908`) + полный `container.innerHTML = ...` (`renderer.ts:1035`) + перезагрузка Google Fonts link и `document.fonts.load` (`renderer.ts:921-988`) + ремоунт инспектора `{#key inspectorTick}`.
- Сделать по шагам: (а) кэшировать fonts-link и не трогать при ререндере; (б) точечное обновление изменённых узлов дерева по diff (id-ключи уже есть в IR); (в) инспектор — точечные апдейты вместо ремоунта.
- Эффект: правки большого импорта перестают лагать; метрика — p95 longtask < 150мс уже измеряется тестами.

### 2.4 Autosave: уйти от O(весь проект) на каждое сохранение (P1)
- Фронт: глубокий обход + stringify + синхронный `localStorage.setItem` в idle-слоте (`serialize.ts:160-194`).
- Бэк: полная сериализация + двойной SHA-256 + обход taste-profile всех нод под глобальным `BEGIN IMMEDIATE` (`project_store.py:239-281, 393-415`). Бюджет «autosave p95 ≤ 250мс» задокументирован, но не проверяется (`perf_scale_test.py:12-16`).
- Сделать: бэк — инкрементальные записи (дельта по нодам) или хотя бы вынести taste-profile/prompt-events из горячего пути; фронт — async Clipboard/IndexedDB вместо синхронного LS; добавить assert бюджета в перф-тест.
- Эффект: снимает фризы при активном редактировании больших проектов.

### 2.5 Загрузка приложения без фриза на старом localStorage (P1)
- Сейчас: легаси-блоб ≥400КБ синхронно `JSON.parse`-ится до первой отрисовки (замер в комментарии: 18МБ → FCP 3.2с; `store.ts:571`, `serialize.ts:585-599`).
- Сделать: скелет-экран + перенос парсинга в `requestIdleCallback`/воркер; миграцию легаси-данных — один раз, с индикатором.

### 2.6 Тёплые CLI-сессии и кэш промптов (P1)
- `build_system_prompt` перечитывает 4 файла с диска на каждый LLM-вызов (`llm_client.py:333-343`) → memoize по mtime.
- Каждое обращение к Claude = новый процесс `claude -p` (холодный старт JS-рантайма); Codex — эфемерный тред + `mcp.refresh()` с полным stop/респавном всех MCP-серверов перед каждым тредом (`main.mjs:730`, `mcp-manager.mjs:69`).
- Сделать: кэш промптов — сразу; для Codex — не пересоздавать MCP при живых серверах; для Claude — опциональный персистентный headless-режим.
- Эффект: −1–3с на каждый вызов агентов, меньше «почему думает так долго».

### 2.7 Мелочи бэкенда (P2)
- `cache_store`: глобальный lock + новое SQLite-подключение + миграция на каждую операцию + двойное хэширование (`cache_store.py:43,165-179,293-299`) → connection-per-thread + single hash.
- Финальный поллинг source-import глубоко копирует весь multi-МБ результат (`server.py:930-936`) → отдавать ссылку/блоб.
- Таймеры MotionDesign-нод поллят каждые 30с бесконечно, даже когда нода не на экране (`flow/store.ts:1919-1976`) → поллить только видимые/активные.
