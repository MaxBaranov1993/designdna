# UI Kit: задержки проверки мастеров, 2026-09-08

## Наблюдения

Проверен открытый пользовательский граф `slsbmb.com`: 15 компонентов,
8 принятых мастеров, 7 на ревью. `master-review` проверяет каждый из семи
мастеров на desktop, tablet и mobile: 21 визуальный запрос.

В сохранённом состоянии style-review завершился в 17:23:26 UTC;
последняя ошибка master-review в 17:40:44 UTC:
`Codex app-server timed out: account/read`. Позднее account/read снова
ответил за 10 мс. Это наблюдение временного сбоя транспорта, не доказательство
того, что каждый медленный ответ модели вызван зависшим процессом.

В коде обнаружены независимые источники лишнего ожидания:

1. Очередь ждала завершения пары запросов перед запуском следующей пары.
   Быстрый запрос освобождал слот, но этот слот простаивал до ответа соседа.
2. После законченного review → repair → verify внешний цикл мог повторять
   весь процесс ещё дважды. Отклонённые кандидаты не сохраняются, поэтому
   повторно проверялись те же исходные мастера: до 63 review-запросов вместо 21.
3. Полный timeout модели автоматически повторялся один раз, удваивая ожидание.
4. Эфемерные Codex-чаты после визуальных проверок не освобождали подписку
   `thread/unsubscribe`. Эфемерность не означает освобождение runtime-ресурсов.
5. Timeout протокола оставлял процесс отмеченным как инициализированный;
   следующий запрос мог снова попасть в тот же неисправный канал.

## Изменения

- Очередь непрерывно заполняет свободные слоты при прежнем лимите два.
  Ошибка прекращает запуск ожидающих задач; отменяются текущие запросы.
- Завершённый цикл с отклонёнными кандидатами возвращает диагностику.
  Повтор допустим для ограниченного исправления формата ответа, но не для
  автоматического повторения того же полного ревью.
- Полный timeout больше не запускает модель повторно. Сохранён один повтор
  для временных сетевых ошибок и ответов 429/502/503/504.
- Подписка Codex освобождается при успехе, ошибке и отмене, включая поздний
  ответ thread/start после отмены. Timeout протокола сбрасывает неисправный
  процесс; следующий явный запрос инициализирует новый.
- В инспекторе доступны длительности подготовки, AI, применения результата,
  число запросов и сетевых повторов. Время AI суммируется по запросам и при
  параллельном выполнении может превышать полное время этапа.
- Контекст страниц Chromium явно закрывается перед браузером даже при ошибке.

Критерии качества, три размера экрана, точные ссылки на мастера, rollback
непринятых исправлений, модель, reasoning effort и изоляция CLI сохранены.

## Проверки

- Frontend: 142 теста, включая очередь из 21 задачи, отмену, timeout,
  отказ от повторного полного цикла и блокировку публикации при отклонениях.
- Desktop: 352 теста, включая освобождение 21 чата и восстановление после
  зависшего account/read; отдельно проверена отмена до ответа thread/start.
- Backend: 115 тестов review/repair/staging и освобождения renderer-ресурсов.
- Desktop frontend собран: svelte-check — 0 ошибок, 0 предупреждений.
- В отдельном Electron-профиле выполнен полный путь Python prepare →
  21 desktop provider request → Python apply. Ответы модели заменены локальными
  фикстурами; настоящие модели не вызывались. Проверены лимит два, ровно
  21 запрос, отсутствие повторов и успешное применение тестовых вердиктов.

Контролируемый тест очереди с чередованием быстрых и медленных ответов:
848 → 539 мс (36% меньше). Это результат планировщика, не замер ускорения
живой модели. Пользовательские мастера тестовыми вердиктами не изменялись.

## Переменная задержка завершения Chromium

Начальный отдельный замер 21 рендера дал 9,126 с. В повторных Electron-прогонах
подготовка заняла 38–85 с. Профилирование отдельных операций показало, что
контекст закрывается за 11–12 мс, а `browser.close()` занимает 28–56 с.
Журнал Playwright подтверждает задержку ожидания выхода процесса, а не
удаления временного каталога (его удаление заняло 12 мс). Отключение GPU
в диагностическом профиле не устранило задержку и в продукт не внесено.

Явное закрытие контекста обеспечивает корректное освобождение ресурсов,
но **не считается доказанным исправлением всех задержек Chromium**.
Экспериментальный watchdog завершения процессов не сработал по таймеру
и в продукт не внесён: приписывать ему ускорение нельзя.

Последний контрольный прогон на обычном коде, без диагностических перехватов:
11,318 с всего, prepare 8,677 с, apply 1,166 с, 21 запрос, максимум два
одновременно, ноль повторов (`electron-performance-final.log`). Таким образом,
долгое завершение процесса воспроизводилось не в каждом запуске.
Диапазон прогонов с фикстурами AI — 11–90 с; это не измерение живой модели.
Полный живой AI-цикл после изменений не запускался. Новые тайминги позволяют
отделить задержки внешнего браузера от времени ответов Codex.

Артефакты находятся в `artifacts/ds-performance/`. Открытое приложение
перезапущено; граф, Source-данные и ссылки на дизайн-систему сохранены.
