# Конкурентный анализ: Paper (paper.design) и Pencil (pencil.dev / pen.dev)

> Дата: 2026-08-05. Автор: Qwen Code (анализ по запросу владельца).
> Источники: сайты paper.design, pen.dev, docs.pen.dev, страница сравнения
> paper.design/compare/pencil. Pencil дополнительно установлен локально у владельца
> (MCP-сервер — те самые инструменты, которыми уже работают агенты проекта;
> `inspector.js` DesignAI уже копирует инспектор pen.dev).

---

## 1. Paper — «The connected canvas for teams shipping with agents»

**Суть:** веб-нативный холст (реальный HTML/CSS, не проприетарный формат), где
дизайн, код и данные живут в одном пространстве, а AI-агенты (через MCP) читают
и пишут холст наравне с людьми. $34M Series A (Accel, ICONIQ).

**Ключевые фичи:**
- **Design to Code and Back:** двунаправленная синхронизация — агенты обновляют
  токены/стили/компоненты одновременно в коде и на холсте. Холст = HTML/CSS,
  поэтому «экспорт» не нужен: дизайн уже код.
- **Агенты первого класса:** подключение любых IDE/CLI-агентов по MCP; агент —
  участник холста, а не плагин.
- **Реальные данные:** подключение CMS/БД/API/файлов — «goodbye lorem ipsum»,
  дизайн строится на реальном контенте.
- **Агенты берут рутину:** адаптивные лейауты, вариации стилей, проверки
  консистентности («anti-slop»).
- **Коллаборация:** real-time мультиплеер, шаринг по URL; зрители бесплатны
  на всех планах.
- **Тарифы:** Free ($0, 100 MCP-вызовов/нед) / Pro $16 за редактора/мес (год) —
  1 млн MCP-вызовов/нед, экспорт видео / Organizations — SAML/SSO, админка.
  Метрика биллинга = **вызовы инструментов агентами**.

**Слабости (для нашей ниши):** контроль — на стороне промптов и дисциплины агентов;
нет структурного IR, нет детерминированных гарантий («агент написал код на холст»
≠ «структура сохранена»). Локальные/приватные сценарии слабее (облачный мультиплеер).

## 2. Pencil — «Design on canvas. Land in code.»

**Суть:** десктопный (WebGL) редактор + IDE-интеграция; файлы `.pen` (текстовый JSON)
лежат в git рядом с кодом — **Design as Code**: diff/branch/merge дизайна как кода.
Агенты работают через **локальный MCP-сервер**. Пока полностью бесплатен.

**Ключевые фичи:**
- **MCP-инструменты для агентов:** `execute` (Get/Create/Update/Delete узлов,
  `ctx.bounds`/`ctx.problems` для анализа), `GetVariables`/`SetVariables`,
  `get_screenshot`, `get_app_state`, гайды/стили (`get_guidelines`). Агент
  предлагает — пользователь утверждает. Поддерживаются Claude Code, Cursor,
  Windsurf, Codex CLI, Antigravity, OpenCode.
- **Code on Canvas (Script node):** узел выполняет внешний `.js` в песочнице
  (детерминированный `Math.random` по seed, ≤1000 узлов, ≤2 сек) и рендерит
  результат как слои. Заголовок файла объявляет `@input`-параметры
  (number/string/boolean/color/enum/ref) → авто-контролы в панели свойств;
  live-перезагрузка при сохранении файла; «Convert to layers» превращает
  производное в редактируемые слои. Публичная библиотека скриптов
  (`highagency/pencil-scripts`). AI умеет генерировать скрипты по описанию.
- **Design ↔ Code через AI-чат** (нет кнопки Export): генерация кода с указанием
  стека (React/Next/Vue/Svelte, Tailwind/shadcn/Radix…), импорт компонента из
  кода в дизайн, двунаправленная синхронизация CSS-переменных ↔ переменных .pen.
- **Переменные, компоненты, слоты, дизайн-библиотеки.**
- **Границы (по данным Paper):** локальный single-user, нет веба, только Hex sRGB,
  проприетарный формат требует трансляции в HTML/CSS.

## 4. Стратегический вывод

1. **Оба конкурента делают ставку на «агент — автор»**. Paper — агент пишет код
   на холсте; Pencil — агент правит `.pen` через MCP. Ни один не продаёт
   **детерминированный контроль** («структура гарантирована, стиль заперт,
   правила охраняются»). Наша ниша «control plane для AI-дизайна» свободна,
   но окно сужается: если Paper/Pencil добавят локи/правила — дифференциация
   ослабнет. Скорость по Quality Gate + Constraints (решение 12) критична.
2. **Оба сделали MCP стандартом подключения агентов** (Paper — биллинг по
   MCP-вызовам; Pencil — MCP-сервер в IDE). Для нашего первичного сегмента
   (AI-разработчики) отсутствие MCP-входа в DesignAI будет выглядеть архаично.
3. **Pencil уже частично внутри нашего процесса** (MCP-инструменты у владельца,
   инспектор скопирован). Это источник постоянных заимствований UX-паттернов —
   стоит отслеживать их changelog системно.
4. **Paper задаёт планку «данные вместо lorem» и коллаборации** — это ожидания
   B2B-покупателя, которые появятся на демо-звонках; иметь ответ в дорожной карте.
5. **Ценовой ориентир получен:** $16/редактор/мес (Pro), метрика = вызовы
   инструментов; зрители бесплатны. Ложится на нашу гибридную модель
   (подписка = seat, кредиты = генерации/вызовы).

## 5. Идеи к заимствованию (предложения владельцу)

Статус: всё ниже — **предложения**, ждут решения. Привязаны к каталогу
`docs/NODES-HOUDINI.md`.

### Из Pencil

1. **Script-нода (Code on Canvas)** → каталог §1.4, класс **D**.
   Детерминированный JS в песочнице генерирует IR: seed-детерминизм, лимиты
   (≤1000 элементов / ≤2 сек), `@input`-параметры (number/string/boolean/color/
   enum/ref) становятся параметрами ноды. Идеально ложится на D/AI-философию и
   на HDA-ассеты (§2): скрипт с @input ≈ ассет с параметрами. Публичная
   библиотека скриптов = будущий рынок ассетов (§10). **Сильное заимствование:
   расширяет продукт для технических пользователей без затрат на LLM.**
2. **Детерминированный seed** во всех генерирующих нодах (Generator, Batch,
   Wedge): одинаковый seed → одинаковый результат. Воспроизводимость = контроль.
   Дёшево, делается сразу.
3. **Design as Code (git)**: IR — текстовый JSON, уже diff-able. Проект = папка
   IR-файлов в git; дизайн-ревью как код-ревью (diff IR в PR). Развитие Timeline
   (§8.4) «в обе стороны»: git снаружи, Timeline внутри.
4. **Approval-flow для AI-нод** (паттерн Pencil MCP): результат AI-ноды попадает
   в граф не автоматически, а через мини-превью «принять/отклонить» (переключить
   можно в bypass для потоковых сценариев). Прямое усиление киллер-фичи.
5. **Типы параметров @input** → спецификация параметров HDA-ассета (§2):
   number(min/max), string, boolean, color, enum, ref. Не изобретать своё.
6. **Гайды для агентов** (аналог `get_guidelines`): наша `DESIGN-KNOWLEDGE.md` +
   `BLOCKS.md` выставляются как формальные гайды для внешних агентов через
   MCP-сервер (§5.4) — знания становятся продуктовой фичей.

### Из Paper

7. **Data-нода: реальный контент вместо lorem** (§1.1). Вход: CSV/JSON/API/файл;
   выход подставляется в props блоков (тексты, списки, карточки). Для лендингов —
   мгновенная ценность («дизайн сразу с моим контентом»). В IR это slot-заполнение
   по пути.
8. **Шарабельные view-only ссылки**: превью IR/графа по ссылке для клиента
   (посмотреть, прокомментировать) без аккаунта. Дешёвая B2B-фича с большим
   эффектом в продажах; предшественник коллаборации.
9. **Модель «зрители бесплатны»** в тарифы: seat платит редактор, просмотр/ревью
   бесплатны — снижает трение при продаже студиям (клиенты студии = зрители).
10. **Биллинг по вызовам инструментов** как эталон для кредитной части гибрида:
    кредит списывается за операцию (генерация/свип/block-parse), подписка даёт
    пакет + лимиты; видимость стоимости до запуска (уже утверждено в решении 13).
11. **Narrative «anti-slop»**: их позиционирование дословно описывает нашу
    киллер-фичу («рутина — машинам, контроль и вкус — человеку», только у нас
    контроль гарантирован архитектурно). Использовать в маркетинге как
    «anti-slop by construction».

### Синтез: MCP-сервер DesignAI

12. **Собственный MCP-сервер** (Paper + Pencil оба): выставить операции ядра
    (generate/mix/reskin/block-parse/validate + гайды) как MCP-инструменты —
    внешние агенты (Claude Code, Cursor и т.д.) управляют нашим графом/IR из IDE.
    Для AI-разработчиков это самый естественный вход в продукт, и он же делает
    Headless API (§9) «видимым» в их среде. Реализация — поверх тех же
    эндпоинтов; приоритет вместе с §9 (после SaaS-обвязки).

### 5.1. Архитектурный принцип: «один вход, мульти-модельное исполнение»
(разбор сомнения владельца, 2026-08-05)

Сомнение: «если давать пользователям pen.dev-подобный флоу (внешний агент через
MCP), а у нас ноды работают разными нейросетями — подвязка всего под одну модель
убьёт функционал».

**Ответ: нет, при разделении двух слоёв:**

1. **Слой входа (кто управляет)** — единый контракт: MCP/REST выставляет
   **продуктовые операции** (`generate`, `reskin`, `mix`, `block-parse`,
   `validate`, `export`, гайды), а не сырые модели. Внешний агент — оркестратор,
   как пользователь в UI.
2. **Слой исполнения (кто делает)** — мульти-модельный роутинг по ролям
   (AGENTS.md решения 3/7) живёт внутри операций и не меняется: Generator —
   свои провайдеры, Critic — свои, vision — свои. Единый вход не отменяет
   мульти-модельность, а скрывает её сложность от вызывающего.

Ставка продукта: **мозг — наши пайплайны** (роутинг + IR + детерминированный
слой), а не внешний агент (модель Pencil: «ваш агент — мозг, мы — холст»).
Это защищает киллер-фичу: контроль живёт в нашем слое; при свободном рисовании
внешнего агента контроль утекал бы наружу.

**Единственное условие:** если внешним агентам даётся сырая запись в IR
(analog pencil-`execute`), каждая запись проходит охранный слой:
схема → Constraints → merge-back. Это и есть «контроль как API-контракт» (§9).

## 6. Где мы выигрываем (не заимствовать, а подчёркивать)

- **Детерминированный микс и лок структуры** — у обоих конкурентов нет аналога;
  у Paper «агент написал» = непредсказуемо, у Pencil approval не гарантирует
  сохранность структуры.
- **Закрытая библиотека + схема**: консистентность по построению, а не по гайдам.
- **Pixel-perfect reproduction** (diff < 5% из скриншота) — ни у кого нет.
- **Локальность/приватность** как фича (Pencil тоже локальный, но Paper — облако):
  для B2B с чувствительными брендами — аргумент, усиленный решением по Taste
  Memory (opt-in + локальный режим).

## 7. Решения владельца (2026-08-05)

1. **MCP-сервер DesignAI: берём** — вместе с Headless API (§9, NODES-HOUDINI.md),
   по принципу «один вход, мульти-модельное исполнение» (§5.1).
2. **Из Pencil берём всё предложенное:**
   - **Script-нода** (детерминированный JS в песочнице, `@input`-параметры,
     seed, лимиты ≤1000 элементов / ≤2 сек) — в каталог нод, класс D;
   - **детерминированный seed** во всех генерирующих нодах (Generator/Batch/Wedge);
   - **approval-flow для AI-нод**: результат попадает в граф через мини-превью
     «принять/отклонить» (bypass для потоковых сценариев);
   - **Design as Code**: IR-файлы в git, diff/ревью дизайна как кода — развивать
     вместе с Timeline (§8.4 NODES-HOUDINI.md).
3. **Из Paper берём:**
   - **Data-ноду** (CSV/JSON/API/файл → контент в props блоков, «goodbye lorem ipsum»);
   - **view-only ссылки** (превью графа/IR по ссылке без аккаунта — клиентские ревью);
   - модель тарифов **«зрители бесплатны»** (платит редактор) — в гибридную схему;
   - narrative **«anti-slop by construction»** в маркетинге.
4. **Позиционирование: независимый control plane.** Конкурируем гарантированным
   контролем (лок структуры, правила, детерминированный слой), а не количеством
   функций; комплементарный слой поверх чужих холстов не планируется.
5. Типы параметров `@input` (number/string/boolean/color/enum/ref) берутся как
   спецификация параметров HDA-ассетов (NODES-HOUDINI.md §2); гайды
   (`DESIGN-KNOWLEDGE.md`, `BLOCKS.md`) выставляются через MCP-сервер как
   формальные руководства для внешних агентов.
