# Видео: моушн-режиссёр, хореография и камера (2026-09-22)

Нода Video собирает ролик из подключённых страниц (Design IR) и таймлайна. Все движения детерминированы: модель по подписке (Codex → GPT-5.6 Sol / GPT-6 Astra, Claude Code → Fable 5.1 / Opus) предлагает только план, кейфреймы генерирует код, результат — обратимый `TimelineChangeSet`.

## Три пути запроса в видео-чате

| Запрос | Путь | Вызовы модели |
| --- | --- | --- |
| Только движение («плавный продуктовый ролик», «cinematic camera») | `timeline_director.plan_from_llm` → хореография | 1 короткий текстовый вызов, без скриншотов страниц |
| Взаимодействие, состояния, переводы («кликни по меню», «переведи страницу») | `video_story.direct_story` | vision-анализ страниц + план сценария (2 вызова) |
| Провайдер недоступен и `require_llm` не задан | `plan_from_prompt` по ключевым словам и шаблонам | 0 |

Классификатор `timeline_choreography.is_motion_request` требует положительного словаря движения и отсутствия слов взаимодействия; ответ на уточняющий вопрос режиссёра всегда идёт сценарным путём. Моушн-путь никогда не переписывает `story`.

## Словарь движения

Пресеты (`ir/timeline.py`, `PRESET_NAMES`): `fade-in`, `fade-in-up`, `slide-in-left`, `slide-in-right`, `zoom-in`, `scale-reveal` (мягкий overshoot), `focus-pull` (размытие 14 px → резкость), `wipe-reveal` / `wipe-out` (маска-шторка снизу), `rotate-in`, `zoom-spotlight` (1→1.12), `hero-focus` (1→1.04), `dim` (→0.35), `defocus` (0→6 px), `fade-out`, `pan-down`, `drift-up` (параллакс), `cta-pulse`, `cta-bounce`, `camera-push`, `camera-pull`, `camera-pan`, `camera-drift`.

Анимируемые свойства слоя: `x`, `y`, `scale`, `rotation`, `opacity`, `blur` (px, 0..64; `filter: blur()`), `clip` (процент слоя, скрытый снизу, 0..100; `clip-path: inset()`). Оба идут в движок превью, story-плеер, экспорты CSS/WAAPI и офлайн-рендер; в инспекторе редактора они редактируются как обычные треки. Схема `timeline-ir` расширена без миграции: старые документы без этих треков валидны.

Кривые пишутся как `cubic-bezier` из `NAMED_CURVES`: `expo-out`, `quart-out`, `back-out`, `smooth`, `cinematic`. Параметры шага: `start`/`duration` в долях ролика, `staggerMs`, `travel` (px), `curve`.

Шаблоны (`timeline_choreography.TEMPLATE_NAMES`): `product-showcase`, `presentation`, `feature-tour`, `clean-reveal`, `cinematic-camera`. Шаблон раскладывает секции и их элементы по ролям (heading → text → image → button) и добавляет камеру; модель кладёт поверх до 6 акцентов.

`normalize_steps` держит ритм: ревейлы 450–1600 мс, stagger ≤220 мс, неизвестные пресеты и слои отбрасываются, медленные пресеты (камера, spotlight, drift, dim) сохраняют длительность. `merge_keyframe_operations` сливает кейфреймы одного свойства между шагами и с существующим треком, поэтому «появление + затемнение» на одном слое не затирают друг друга.

## Переходы между страницами сценария

`navigate.transition`: `cut`, `fade`, `motion`, `state`, а с 2026-09-22 ещё `slide` (следующая страница выталкивает текущую вверх, как слайд) и `zoom` (следующая страница садится из лёгкого увеличения, предыдущая отступает). Реализованы в `VideoStoryPlayer.seek`, доступны режиссёру сценариев и в селекте «Transition» панели сценария.

## Камера

Слой `camera` (тип `camera`, один на документ) добавляется операцией `add-layer` при первом камерном пресете. Движок применяет его трансформацию к обёртке `[data-timeline-camera]`: в превью редактора это `.tlw-camera`, в story-плеере — обёртка страниц внутри host, в офлайн-рендере — `.timeline-camera` вокруг `#host`. Секции продолжают анимироваться своими слоями. Экспорт CSS/WAAPI выводит камеру как обычный слой `camera`.

Пролёт `camera-pan` считается из реальной геометрии: плеер редактора измеряет высоту каждой отрисованной страницы (`VideoStoryPlayer.pageHeights`) и отправляет её в `/api/timeline/assist` как `pageHeights`; без измерения `_page_geometry` берёт `frame.height` секций IR, а без геометрии — консервативную оценку (720 px на секцию, пролёт не больше 1.2 высоты кадра).

## Рендер

`render_timeline_video(..., workers=N)`: при N > 1 кадры режутся на смежные сегменты, каждый рендерится своим Chromium и ffmpeg, сегменты склеиваются без перекодирования (`_concat_segments`). Автоматика: один воркер до 90 кадров, дальше до трёх (половина ядер), потолок `MAX_RENDER_WORKERS = 4`, переопределение `DESIGNDNA_RENDER_WORKERS`. Кадры идентичны одиночному режиму, отмена или ошибка одного воркера останавливает остальные, временные сегменты удаляются.

## Модели

Каталог `video_models.catalogue()`: Codex-модели из локального кэша (`gpt-5.6-sol`, `gpt-6-astra` по умолчанию) и Claude `fable` (Fable 5.1), `opus`. Десктопный адаптер принимает `fable` в `--model`; проверено на Claude Code 2.1.190.

## Сценарий с формой и финальным логотипом (2026-09-24)

Проверено на slsbmb.com с Claude Opus: прокрутка страницы до формы, ввод в три поля, клик по кнопке, переход `zoom` на вторую страницу с логотипом, появление логотипа и слогана. Ролик 24 с.

- Цели сценария (`video_story.targets`): проверка видит все элементы страницы. Модели показывается не больше `PROMPT_TARGET_LIMIT` (512): сначала корни секций и элементы управления (`input`, `button`, `textarea`, `select`, `link`), затем остальное поровну по секциям. Раньше срез первых 512 узлов отрезал форму в конце страницы из полос Source, и шаги по её полям отклонялись.
- Анализ страницы перед планом: ссылка на несуществующий элемент больше не отменяет запрос. Такие ссылки отбрасываются и передаются планировщику списком «не использовать»; страница, названная по имени («Logo»), сопоставляется со своим id. Отказ остаётся, если среди названных элементов нет ни одного настоящего.
- Режиссёр продлевает ролик для длинной страницы (`extend_for_long_page`, до 20 с), чтобы панорама дошла до конца страницы; сценарный путь сам удлиняет ролик под действия.
- Финальный кадр делается второй страницей ноды Video (например, Edit с IR). В проверенном прогоне это логотип сайта из захваченной шапки, увеличенный в 5 раз, со слоганом героя.
