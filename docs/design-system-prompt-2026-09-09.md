# Дизайн-система в промпте генератора (2026-09-09)

Что получает модель из дизайн-системы, в каком порядке и почему. Код: [app/design_system/compiler.py](../app/design_system/compiler.py), [app/design_system/master_summary.py](../app/design_system/master_summary.py), [app/design_system/reference_images.py](../app/design_system/reference_images.py), сборка в [app/api/generate.py](../app/api/generate.py).

## Диагноз, с которого всё началось

Лендинг по UI Kit slsbmb.com выходил «правильным по токенам, но нейрослопным»: те же цвета и шрифты, но общий шаблон вместо характера источника. Причины были в компиляторе контекста:

| Проблема | Было | Стало |
| --- | --- | --- |
| Бюджет extend/style-only | 1200 токенов: мастера, ревью стиль-гайда, DO/DON'T, покрытие палитры и план тестов отрезались, бриф сайта обрывался посреди слова | 8000 токенов по умолчанию (`compiler.default_budget`), strict 32 000 |
| Мастера в контексте | только полный `masterIr` (десятки тысяч символов на секцию): в strict помещались 3 мелких, в extend ни одного | сводка каждого мастера ~150–250 токенов: корень, анатомия с образцами текста и типографикой ролей, декоративные признаки, токены привязки; полный IR только в strict и для пиннутого референса |
| Декоративный язык | не описывался | сигнатуры из мастеров: моно-лейблы, статус-пилюля с точкой, стрелки в CTA, разделители «·» и «/», нумерация шагов, однострочная форма с префиксом, тонкие рамки, цветные тени, инициал-аватар, фоновые градиенты; с примерами из источника |
| Архетип | `archetypes[0]` — самый частый вид блока («Gallery») для любого брифа | явный id → упоминание в брифе (синонимы: тариф → Pricing, шаги → How It Works) → для страницы все виды секций → для компонента без совпадения ничего |
| Порядок строк | числовые шкалы раньше атмосферы, ревью после мастеров и без `required` | характер раньше цифр: душа → профиль стиля → декор-сигнатуры → бриф сайта → ревью и DO/DON'T → цвета/тип/геометрия → реестр |
| Шкалы | 27 строк `size6…size27`, 35 `spaceN` | именованные ступени плюс компактная выборка остальных значений |
| Картинки | не передавались | до трёх референсов: целые блоки источника, где живут релевантные мастера, и кроп самого мастера (JPEG ≤ 1100 px по ширине, суммарно ≤ 2,5 МБ) |

На реальном UI Kit (15 мастеров) extend-профиль занимает ≈4 300 токенов из 8 000, все правила включены, сводки всех 12 мастеров контекста присутствуют. Раньше на 1 200 токенах включённых мастеров было ноль и одиннадцать правил отбрасывалось.

## Порядок и обязательность строк

`compile_profile` добавляет строки в порядке приоритета; при нехватке бюджета обязательные (`required`) строки укорачиваются, необязательные пропускаются и попадают в `omittedRuleIds`.

1. `system.ref`, `policy.usage-mode` — режим первым, а не последним.
2. `identity.soul`, hard/soft `BAN`.
3. `styleguide.profile` — атмосфера: тема, углы, плотность, `labelStyle`, `monoFamily`, голос копирайта.
4. Декор-сигнатуры (`sig-*` из `master_summary.decorative_signatures`), затем измеренные сигнатуры identity.
5. Архетипы (`select_archetypes`).
6. `site.brief` — ужимается по смыслу (`compact_site_brief_levels`), а не режется посреди JSON; `site.component-usage`.
7. `styleguide.review`, `styleguide.do.N`, `styleguide.dont.N` (все `required`), `styleguide.component-notes`.
8. `foundations.colors`, `foundations.typography` (компактно), `foundations.geometry`, `styleguide.tokens`, `styleguide.character`, `identity.palette-coverage` (шесть главных ролей).
9. Реестр: контракт вариантов, в strict контракт `componentRef`, `registry.summary-contract`, `registry.summary.<key>` для каждого мастера, `registry.master.<key>` (точный IR) для strict или пиннутого, `registry.components`.
10. `identity.test-plan`, `fixture.selected`.

Резерв под пиннутый мастер сохранён: строки до него не могут занять его место, `strictReady` считается как раньше.

## Референс-картинки

`reference_images.select_candidates(document, context, surface)` выбирает кандидатов из `referenceAssets` по мастерам контекста (в порядке релевантности): для страницы сначала разные блоки источника, затем кроп самого релевантного мастера; для компонента сначала кроп, потом его блок. Кандидаты пишутся в `generationLog.designSystem.referenceImages` всегда; декодирование (`render`) выполняется только когда промпт уходит модели (`prepareOnly` или прямой вызов), на проходе `rawOutputs` нет. Части `image_url` с data:image/jpeg принимают все транспорты: OpenAI Responses, `claude -p` (временный файл + Read), Codex app-server (`localImage`), `codex exec -i`.

Текст сообщения получает блок «Визуальные референсы» со списком картинок и правилом: перенимать композицию, ритм, рамки, бейджи, лейблы, стрелки и точки, но не копировать контент.

## После ответа модели: что ещё ломало верность системе

Сравнительный прогон лендинга ноды 29 (extend, Claude high) показал, что часть характера терялась уже после генерации:

| Симптом | Причина | Исправление |
| --- | --- | --- |
| Белые поля между секциями, заголовок наезжает на надзаголовок | модель написала auto-layout (`direction`/`gap`/`align`/`padding`/`width`) прямо на `frame` секции-композиции, а рендерер применяет frame секции к обёртке вокруг `<section>` | `sanitize_generated_ir` переносит раскладку в дочерний `frame`, на секции остаётся рельс `contentMaxWidth`/`contentGutter`; BLOCKS.md говорит об этом явно |
| Лейблы 9–11px «лечились» до 12px | правило `min-font-size` не знало шкалу сайта | с ДС порог опускается до наименьшей ступени измеренной шкалы, не ниже 9px (`qualitygate.min_font_rule`, `style_review.label_size_floor`) |
| JetBrains Mono снимался с лейблов | IR-токены знают только display/body, DS-lint считал третью гарнитуру чужой | захваченные faces мастеров попадают в `meta.fontFaces` результата (`style_review.font_faces`): lint признаёт семейство, рендер и редактор грузят файлы |
| Предупреждения «радиус 999 вне шкалы» | пилюля проверялась как число из шкалы | радиус ≥ 50 при наблюдённых пилюлях (или `radius-button` ≥ 50) не считается отступлением |
| Заголовок секции дважды (слева белым и в дереве) | модель дублировала текст в `props.heading` и в дочернем `heading` | `props.heading`/`subheading`, повторённые дочерним текстом, снимаются |
| Форма 640px вылезает за экран 390px | фиксированная ширина контейнера в колонке | ширина > 360px у контейнера/поля/кнопки в колонке становится `fill` + `maxWidth`; в рядах и free-раскладках не трогается |
| Префикс «https://» обрезан до «h», кнопка формы переносит текст | рендерер сжимал текст в ряду до нуля (`flex:1 1 0; min-width:0`), кнопка с `fill` делила ширину с полем | рендерер: текст в ряду не уже `min-content`; санитайзер: в ряду с полем ввода короткие лейблы и кнопки получают `hug` |

Параллельная проверка в приложении 2026-09-10 (две ноды: Claude Opus style-only и GPT-6 Astra extend) прошла до конца с Quality Pass: генерация 150 и 217 с, починка 167 и 357 с, арт-дирекция Astra через Codex 76 с. Эталоны `app/exemplars` через санитайзер проходят без изменений.

## Арт-направления знают систему

Раньше с подключённой ДС стадия арт-дирекции не вызывалась вовсе: политика подставляла три фиксированных плана («Задача на первом месте», «Сравнение и контекст», «Последовательное решение»), одинаковых для любого сайта. Теперь для лендинга в extend/style-only генератор передаёт модели `designSystemDigest` (`compiler.direction_digest`): душа, профиль стиля, декор-сигнатуры, ревью с DO/DON'T, бриф сайта и его секции, голос копирайта, виды секций и анатомия шести главных мастеров. Промпт арт-дирекции фиксирует палитру, шрифты, геометрию и декор и просит различать направления композицией, порядком секций, формой hero, ритмом и углом копирайта, называя мастера и декоративные приёмы, на которые опирается направление. Ключ кэша включает дайджест, поэтому направления обновляются вместе с ревизией системы. Strict и компонентные поверхности по-прежнему берут планы политики; при отказе провайдера они же остаются запасным путём.

В десктопе арт-направления считает провайдер через транспорт Electron (профиль `art_direction`, см. [AGENT-CONTRACT.md](AGENT-CONTRACT.md), раздел 3a): сервер отдаёт промпт в `artDirection.messages`, клиент возвращает ответ в `artDirectionRaw`. Python-путь (dev, MCP) по-прежнему зовёт модель сам.

Блок ДС теперь входит в промпт один раз, в user-сообщении рядом с задачей и референсами; раньше он дублировался в system-промпте (~4k лишних токенов).

Побочный эффект направлений: бриф описывает ритм словами `airy`/`balanced`/`dense`, а `props.density` секции принимает `tight`/`normal`/`airy`; модель переносила слова брифа в IR, и вариант целиком не проходил схему. `sanitize_generated_ir` сопоставляет эти синонимы. Список направлений в кэше хранится как объект `{"directions": [...]}` — `cache_store` не принимает списки, и без обёртки второй проход десктопа не находил направления, под которые собирался промпт.

## Что видно в ноде

`generationLog.designSystem`: `mastersInContext` (точные), `summariesInContext`, `decorSignatures`, `archetypeSelection` и `archetypeIds`, `estimatedTokens`/`tokenBudget`, `referenceImages` (с `attached`/`skipped`), `identityScores` по вариантам и `artDirectionAware`. Нода генератора показывает число сводок, сигнатур, оценку контекста, список референсов и identity-оценку каждого варианта (ниже 70 помечается как отход от характера системы).

## Проверки

- `app/design_system_master_summary_test.py` — сводки (компактность, склейка переносов строк, лимит анатомии), сигнатуры, приоритеты и бюджеты компилятора, выбор архетипа, компактные шкалы.
- `app/design_system_reference_images_test.py` — выбор и рендер референсов, части `image_url` в `prepareOnly`, отсутствие декодирования на проходе `rawOutputs`.
- Старые наборы компилятора и strict-восстановления проходят без изменений.

## Что осталось

- В `resolve_context` в контекст входят 12 мастеров (`MAX_COMPONENTS_IN_CONTEXT`); при сводках по 200 токенов лимит можно поднять.
- `identityScore` показывается в ноде, но не блокирует шаблонную анатомию и не входит в Quality Pass.
- Quality Pass (`/api/quality`) не знает дизайн-систему: его автофикс снова поднимет 9–11px лейблы до 12px.
