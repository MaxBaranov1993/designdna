# Backend-ревью 2026-09-08

Разбор архитектуры бэкенда с точки зрения удобства работы для агентов Claude и Codex, которые развивают проект, и надёжности продукта, который ставят другие пользователи. Вопрос «нужен ли PostgreSQL» разобран отдельно в конце.

## Что есть

- FastAPI-монолит [app/server.py](../app/server.py) и четыре роутера: `editor_assist`, `design_system/api`, `timeline_api`, `video_api`. В десктопе тот же ASGI-объект живёт внутри Python-воркера ([app/desktop_worker.py](../app/desktop_worker.py)) и получает запросы JSONL по stdio.
- Хранение: `projects.db` (проект одним JSON с CAS-ревизией SHA-256), `design_systems.db` (реестр и неизменяемые ревизии), `cache.db` (TTL и LRU-бюджет), blob-файлы по хэшу в `data/blobs`.
- AI: Python-клиент ([app/llm_client.py](../app/llm_client.py), [app/cli_llm.py](../app/cli_llm.py)) и отдельно Electron-стек (`provider-router.mjs`, `codex-app-server.mjs`, `claude-agent-server.mjs`). Продуктовый путь — только подписочные CLI пользователя; см. [AGENT-CONTRACT.md](AGENT-CONTRACT.md).
- Агентские интерфейсы: stdio MCP-сервер ([app/designdna_mcp_server.py](../app/designdna_mcp_server.py)) и `skills/designdna/SKILL.md`.

## Что мешает агентам

1. **Нет входа в проект.** README ссылался на восемь документов, которых нет. В корне не было `AGENTS.md` и `CLAUDE.md`. Исправлено: добавлены [AGENTS.md](../AGENTS.md) и [CLAUDE.md](../CLAUDE.md), README указывает на существующие документы.
2. **Монолит как точка конфликтов.** Каждый коммит трогает `server.py`; параллельные агенты сходятся в одном файле.
3. **Два AI-стека с одним контрактом.** Провайдер, модель, усилие, envelope реализованы и в Python, и в Electron. Контракт запуска CLI выровнен 2026-09-08, но транспорт по-прежнему двойной.
4. **История запусков живёт в памяти.** Реестр запусков и задания импорта и рендера теряются при рестарте; лог генерации есть только в HTTP-ответе.
5. **Логирования нет.** Один `print`, корреляции по `runId` нет.
6. **Слой хранения размазан.** Три модуля открывают SQLite по-разному, путь к данным вычисляется в пяти файлах, версии схемы и миграций нет.
7. **Контракты дублируются руками.** Pydantic-модели только для запросов, ответы словари, OpenAPI выключен, TypeScript-типы переписаны вручную.
8. **Тесты без конфигурации.** Нет `pyproject.toml` и маркеров; «выбранный набор» живёт списком в `ui_smoke.py`.

## PostgreSQL

Не нужен. Продукт локальный, один пользователь, один процесс, данные на десятки мегабайт. PostgreSQL добавит установку и обновление сервера на каждой машине, порт, сервис и бэкапы, а взамен ничего. SQLite с WAL — правильный выбор. Проблема не в движке, а в отсутствии единого слоя доступа, версии схемы и истории запусков.

PostgreSQL станет уместен, если появится хостинговый многопользовательский сервер или общий реестр дизайн-систем. Тогда его следует спрятать за тем же `storage/`, который предлагается сделать сейчас.
