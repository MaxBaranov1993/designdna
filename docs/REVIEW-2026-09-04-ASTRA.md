# DesignDNA: выбор моделей и обзор проекта

Основа: `codex/unified-motion-design`, commit `f83c51bccabeff055982dbe0e3ad7f2e707867e5`.
Дата: 2026-09-04. Это обзор кода и контрактов; визуальный UX-аудит не завершён: облачный браузер отклонил локальный preview с `ERR_BLOCKED_BY_CLIENT`. Реальные платные вызовы моделей не выполнялись.

## Что изменено

- Sol и Astra используют один OpenAI API key и Responses API. Выбор Astra поддержан в Generator, Reskin, Derive, Source Import, AI-инспекторе, ревью/организации Design System и планировщике Motion Design. Claude остаётся выбираемым аккаунтом.
- Старые `openai`-проекты продолжают открываться как Sol. Явная Astra сохраняется в проекте. Неподдерживаемые исторические провайдеры мигрируют по прежнему правилу. Отсутствие ключа при явном выборе GPT теперь даёт ошибку подключения, а не переключение на CLI.
- Desktop IPC сохраняет выбранный model, включая Claude Opus/Sonnet/Haiku в запросах. Нормализация вынесена в `prepareProviderRequest` и проверена сквозным тестом до HTTP payload.
- В Agents добавлен выбор Sol/Astra/Claude Opus; Claude получает профиль обычного чата. Его текущий CLI-адаптер не исполняет MCP-инструменты приложения; ограничение видно рядом с селектором. MCP-цикл остаётся доступен у GPT.
- Browser AI-инспектор передаёт выбранные provider/effort; раньше UI отправлял их не полностью, а сервер принудительно вызывал OpenAI.
- Quality Pass наследует модель и effort. Убрана скрытая замена Claude Opus на Sonnet в desktop-ревью.
- Запасной путь распознавания скриншота использует выбранную модель; его кэш разделён по AI-маршрутам.
- Source Import сохраняет и использует effort из селектора: раньше он показывал Medium, игнорировал изменения и местами исполнял High.
- Desktop Responses сохраняет изображения и `responseFormat`; раньше адаптер молча терял оба поля.
- Неполный ответ Responses (`incomplete`/`failed`) не принимается за успешный документ.
- История агента хранит модель и effort конкретного ответа; служебные UI-поля исключаются из следующего API-запроса. Смена модели не переименовывает прежние ответы.

Продуктовые уровни усилия остаются `medium`, `high`, `max`. Полный набор возможностей API не выставляется автоматически. Официальный идентификатор Astra и Responses-возможности проверены по [документации OpenAI](https://developers.openai.com/api/docs/models/gpt-6-astra).

## Оценка идеи

Самая убедительная ценность DesignDNA — цепочка «источник → проверенные редактируемые мастера → дизайн-система → новые экраны с сохранением стиля». `sourceKey`, точные мастера, варианты, ограничения редактирования и контроль сходства дают этой идее техническую основу.

Для первого коммерческого сценария я бы выбрал дизайнеров и небольшие команды, регулярно создающие новые страницы существующего продукта. Измеримый результат: импортировать небольшой реальный сайт, получить пригодный UI Kit, собрать новую страницу и сохранить её после ручных/AI-правок. Важно измерять время до этого результата, долю принятых мастеров и число ручных исправлений.

Motion расширяет тот же сценарий: из утверждённого интерфейса получается презентационный ролик. До стабилизации основного редактора это дополнительный режим, иначе одновременно приходится поддерживать качество импорта, редактора, генератора, временной шкалы и внешней генерации видео.

## Архитектура

| Часть | Сильная сторона | Следующий шаг |
|---|---|---|
| Svelte + Flow | Граф, страницы и редактируемый IR уже связаны | Разделить orchestration и graph state в `flow/store.ts` (~3 466 строк) |
| Electron + Python workers | Локальная обработка, отдельные процессы и supervision | Единые контракты отмены, прогресса и ошибок для web/desktop |
| Design IR / Design System | Схемы, стабильные ссылки, exact masters, fidelity gates | Контрактные fixtures для всех преобразований и миграций |
| Хранение | Ревизии, CAS, защита конфликтов, локальные assets | Тесты полного цикла сохранения/восстановления сложного проекта |
| AI-маршрутизация | Уже есть общий envelope и отдельные адаптеры | Версионируемый каталог: connection, model, capabilities, effort; генерировать TS/Python типы |
| UI-редактор | Одна поверхность, scope, preview/accept, undo | Разделить `controller.ts` (~3 087 строк) и DS-панель (~1 961 строк) по задачам |

Текущий стек пригоден для продолжения. Переписывание на другой стек сейчас не решит основной риск: одинаковые правила повторяются в frontend, IPC и Python. Найденные потери model/image/format/effort — конкретное следствие этого расхождения.

Отдельно: `astra` в текущем совместимом формате проекта — UI-маршрут, а сетевой провайдер — OpenAI. Следующая миграция формата должна разделить эти понятия: `{provider: "openai", model: "gpt-6-astra"}`. Сделать миграцию явно, с чтением предыдущего формата, а не массовой заменой сохранённых проектов.

## UX по коду: предварительные выводы

| Сценарий | Что уже есть | Что улучшить |
|---|---|---|
| Старт | Три готовых сценария в EmptyState | После выбора сценария показать один следующий шаг и нужное подключение |
| Импорт → UI Kit | Evidence, review pool, fidelity gate | Показывать причину отказа и конкретное доступное действие рядом с мастером |
| Генерация | Бриф, направления, DS, варианты, ревью | Одна компактная сводка перед запуском: модель, усилие, варианты, включённое ревью |
| AI-правка | Область изменения, ограничения, preview/accept | Понятный diff «что изменится», закреплённый результат и быстрый откат |
| Граф | Undo, страницы, порты, быстрые шаблоны | Режим пошаговой работы поверх графа для первой сессии |
| Motion | Recorder, Motion Editor, Video Editor, Motion Design | Развести пользовательские задачи: анимация интерфейса, монтаж, генерация видео |

Нельзя подтвердить без экранов: читаемость и контраст, переполнения панелей, порядок фокуса, поведение при перетаскивании и работу при узком окне. Наличие ARIA и проверок Svelte не доказывает доступность всего интерфейса.

## Приоритеты улучшений

1. **Надёжный основной сценарий.** Набор из 5–10 реальных эталонов: импорт → UI Kit → новая страница → правка → перезапуск → экспорт. Измерять результат и стоимость всей цепочки.
2. **Одна AI-конфигурация.** Общий выбор по проекту плюс явное переопределение на ноде. Фактическая модель и причины fallback должны быть видны в результате. Переключение между платными моделями — по выбору пользователя.
3. **Пересчёт изменившихся веток.** Использовать хэш входа, версии правил и модель для invalidation/cache. Изменение текста одной секции не должно повторно генерировать всю страницу.
4. **Сравнение и принятие правок.** Before/after, список затронутых слоёв, закрепление удачного результата, возврат к версии.
5. **Понятный прогресс и бюджет.** Число реальных AI-вызовов, этап, возможность отмены; отдельно обозначать ревью и repair, которые добавляют вызовы.
6. **Укрепление тестов.** Сохранить проверки поведения и контрактов; постепенно заменить проверки буквального текста исходников, которые ломаются при переводе подписи или рефакторинге.

## Проверка

- `npm --prefix frontend run build`: успешно; Svelte check — 0 ошибок и предупреждений.
- Целевые desktop/provider/Claude/MCP-contract тесты: **102 passed**.
- Целевые Python transport/generator/editor/DS/quality тесты: **76 passed**.
- Полный desktop прогон до добавления последнего chat-profile теста: **234 passed, 2 failed**; оба отказа — `listen EPERM` при создании UNIX socket, ограничение среды.
- Полный Python прогон: **570 passed, 16 failed, 19 errors**. Большинство отказов связано с отсутствием Chromium, включая вторичные ошибки рендера. Assertion в `design_system_master_review_test` отдельно воспроизведён на исходном commit.
- Frontend Node suite: **13 passed, 5 failed**; те же пять проверок исходного текста падают на исходной ветке. В baseline без установленного frontend runtime дополнительно недоступен engine regression runner.
- Реальные API-вызовы и визуальные browser/Electron smoke-тесты не выполнены. Перед merge нужны CI и проверка в desktop с подключёнными аккаунтами.
