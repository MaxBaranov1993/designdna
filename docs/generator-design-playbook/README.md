# DesignDNA Generator: руководство по качеству веб-дизайна

Версия 1.0 · 6 сентября 2026 · Для GPT и Claude · Язык документации: русский.

**Главное правило: выбранная дизайн-система определяет визуальный язык и доступные компоненты. Генератор проектирует решение задачи внутри этих ограничений. Если дизайн-системы нет, он сначала создаёт согласованные основы дизайна, затем собирает интерфейс.**

Качество — сочетание полезного сценария, ясной информации, узнаваемого характера, точного исполнения и проверяемого поведения. Одного красивого первого экрана недостаточно.

## Как использовать

**Разработчику генератора:** начать с 06; runtime выбирает компактные правила из версионированного JSON по режиму. Документы 01–03 нужны для выборки релевантных знаний, а не для загрузки целиком в каждый запрос. Проверки из 05 должны работать независимо от модели.

**GPT/Claude при проектировании:** прочитать ядро 04, получить закреплённую DS и точный выходной контракт; выбрать только нужный сценарий из 03; проверить результат по 05. Не устанавливать UI kit только потому, что он упомянут в исследовании.

**Дизайнеру/ревьюеру:** проверить сценарий и характер по 01/03, затем изучить реальный рендер и состояния. Оценивать соблюдение выбранной DS, а не собственный любимый стиль.

## Статус и границы исследования

- Правила подключены к runtime Generator: сценарии, стили, DS-приоритет, контекст двухфазной генерации и защищённый Quality Pass. См. [реализацию и проверки](06-integration.md). Улучшение художественного качества на живом сравнительном наборе GPT/Claude пока не измерено.
- Исследованы профильные локальные скиллы и публичные первичные источники. «Все популярные» здесь означает охват основных классов: арт-дирекция, дизайн-системы, UX/a11y, адаптивность, motion, референсы, UI kits, AI kits и проверка результата. Это не полный реестр интернета и не рейтинг по числу установок.
- Публичные документы компаний дают переносимые методы, но не доказывают, что любое их решение повышает конверсию. Исторические публикации Airbnb и Meta помечены датами.
- Mobbin MCP вернул `Mobbin MCP requires a paid plan`. Скриншоты и реальные flows не получены. В пакет включены публичные сведения и воспроизводимый протокол будущего исследования, без выдуманных наблюдений.
- Текст главной страницы Циан доступен; закрытая DS Циан не изучалась. Визуальный аудит сайтов компаний и пользовательские исследования в этой работе не проводились.
- Числовые пороги со словами «политика DesignDNA» — предлагаемые настройки продукта. Они не приписываются Google, Airbnb или стандартам WCAG.

## Основные решения

1. Приоритет DS выше трендов, пресетов, UI kits и вкусовых скиллов. Конфликт доступности с мастером явно фиксируется и исправляется в DS, а не скрытой мутацией экземпляра.
2. Нельзя объявлять `strict` успешным, если результат фактически принят через `extend`.
3. Рабочий кабинет, каталог, редактор и статья не обязаны содержать hero, отзывы, тарифы и финальный CTA.
4. Inter, белый фон, карточки, симметрия, фиолетовый и serif не являются дефектами сами по себе. Дефект — решение без связи с задачей или нарушение ограничений.
5. UI kit даёт заготовки компонентов; AI kit — ещё и AI-состояния. Ни один из них не заменяет проектирование продукта. Например, [shadcn/ui](https://ui.shadcn.com/docs) описывает открытый код и композицию компонентов, а [Gravity AIKit](https://gravity-ui.com/libraries/aikit) — набор строительных элементов AI-чата.
6. GPT и Claude получают одинаковые требования и доказательства. Меняется адаптер вызова, не критерий красоты.
7. Любая доработка повторно проходит проверку схемы, DS, рендера и сценария. Непроверенный результат остаётся непроверенным.
