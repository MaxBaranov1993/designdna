# Design Studio v3 — первоклассный дизайн в ноде «Генератор»

Дата: 2026-09-03. Аудит качества генерации и архитектура решения. Ориентир — как устроен Claude Design (Design Components: модель пишет настоящий HTML/CSS с инлайн-стилями, flex/grid, Google Fonts, oklch-палитра; ремесло держат правила «settle the aesthetic», «bold direction», запрет AI-слопа, «copy is the product», варианты как артборды).

## 1. Что генерируется сейчас (факты)

Сэмпл: seller-страница rsale (`data/rsale-e2e-profile`, генератор node 5, `results/gen_sample_rsale_full.png`).

- Страница читается как **wireframe с брендовыми цветами**: серый градиент-заглушка в hero, две одинаковые карточки «24/7 · 0 ₽», секция «Три шага» с пустым «Шаг 2», футер сплошной фиолетовой плитой.
- Токены плоские: `surface == background` (белое на белом, ритма нет), `textMuted #2b2b2b` (почти чёрный), **body Manrope 700** (весь текст жирный — дефект извлечения ДС).
- Типографика: фиксированные `calc(17px*var(--fs))`, заголовки маленькие, нет шкалы ролей.
- Композиция: `hero split → feature-grid → steps → cta → footer` — одна и та же скелетная последовательность для любого продукта; `designkb.design_direction` меняет только палитру по кругу, не направление.

## 2. Почему (корневые причины)

| # | Причина | Где |

## 3. Целевая архитектура

Принцип: **сохранить Design IR как редактируемое ядро** (это конкурентное преимущество перед Claude Design, где результат — HTML), но дать модели композиционную свободу и замкнуть цикл через пиксели.

### 3.1 Пайплайн `generate` в три стадии

1. **Art direction** (быстрая модель, ~2 с). Вход: бриф, тип продукта, Style DNA/ДС если есть. Выход `DesignBrief` (JSON, схема `schema/design-brief.schema.json`): аудитория и задача; `tone` из именованных направлений (editorial, brutalist-minimal, soft-pastel, luxury, playful, industrial, retro-futuristic, organic…); `typePair` из расширенного курируемого списка характерных пар (display + body, с fallback-стеками); `palette` — oklch-семя (тон фона, 1–2 акцента с одинаковыми chroma/lightness), из которого сервер детерминированно выводит тональную палитру; `rhythm` — план секций с чередованием плотности и **одним** осознанным риском; `copyDeck` — тезис hero, один CTA, доказательства.
2. **Composition → IR** (сильная модель). Промпт переписывается: режим generate становится основным; в контексте — `DesignBrief`, 2–3 **эталонных IR** (few-shot из `app/exemplars/*.json`, ручной работы, по типам продуктов), правило «секции компонуются из примитивов и auto-layout-фреймов; семантические блоки — ускорители, а не потолок». Вариантов ≥2 — **разные направления**, не разные палитры; у каждого подпись направления.
3. **Pixel critique** (vision-судья). Сервер рендерит IR в PNG (офлайн-путь уже есть: `timeline_render.py` / headless Chromium), судья получает скриншот + рубрику (иерархия, ритм, плотность, типографика, цвет, слоп-тропы, соответствие брифу) → score 0–100 и адресные правки → repair → повторный судья (кооперативная отмена и стадии через `run_registry` уже есть). Порог по умолчанию 80; ниже — нода показывает «нужна доработка» с причинами.

### 3.2 Токены v2

`tokens.v2` (обратно совместимо, миграция в `ir/migrate.py`):
- `color`: `bg`, `bg2`, `surface`, `surface2`, `ink`, `ink2`, `inkMuted`, `line`, `accent`, `accentInk`, `accent2` — генерируются из oklch-семени серверно (`app/colorutils.py`), с проверкой WCAG для всех пар «текст/фон».
- `type`: роли `display/h1/h2/h3/lead/body/small/eyebrow` с `size/lineHeight/tracking/weight`; `families.display/body` + fallback-стек; шкала считается из `base` и `ratio`.
- `space`: шкала 4…160; `radius`: `sm/md/lg/pill`; `shadow`: `sm/md/lg`; `motion`: одна reveal-анимация.
- Рендерер читает роли, а не `calc(17px*var(--fs))`.

### 3.3 Свободная композиция в рендерере

- Секция может быть `type: "composition"`: дерево примитивов (`frame` auto-layout/free, `heading`, `text`, `button`, `image`, `rect`, `divider`) — рендерер это уже умеет для `frame`; нужно снять ограничения промпта и добавить `composition` как первоклассный блок в схему, BLOCKS.md и инспектор.
- Семантические блоки получают **новые варианты с характером** (hero: `editorial-stack`, `poster`, `split-offset`, `numbered`; feature: `list-rail`, `bento-asym`, `two-col-manifest`), фон секций — из `bg/bg2/surface`, не только чередование.
- Заглушки изображений: остаются (пользователь заменяет своим файлом — уже реализовано), но получают арт-дирекцию из `copyDeck.imagery` и **тон заглушки из палитры**, а не серый градиент.

### 3.4 Выбор направления в ноде (как «settle the aesthetic»)

- Генератор показывает 3 чипа направлений (из стадии 1) с одной строкой мотивации и компромисса; пользователь выбирает или «сразу все три»; выбранное направление запоминается в taste-профиле проекта.
- Итог — варианты подписаны направлением, а не «Вариант 1/2».

### 3.5 Эталоны и рубрика

- `app/exemplars/`: 10–15 IR-страниц ручной работы по типам продуктов (лендинг SaaS, маркетплейс, ресторан, портфолио, финтех, e-commerce…), каждая проходит vision-судью на ≥90. Используются как few-shot и как якоря для судьи.
- `app/prompts/RUBRIC.md`: рубрика судьи с примерами «плохо/хорошо».
