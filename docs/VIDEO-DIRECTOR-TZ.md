# ТЗ: нода «Видео» — AI собирает ролик из наших компонентов

Цель одной фразой: пользователь кидает в ноду страницу/компоненты и короткий
бриф, ИИ собирает из них осмысленный ролик уровня «скринкаст сайта, доведённый
в After Effects», пользователь правит его руками на таймлайне и жмёт «Рендер» —
на выходе mp4.

---

## 1. Пользовательский сценарий (то, что должно работать)

1. `Source Import` разбирает сайт → появляются реальные компоненты и токены.
2. Пользователь ставит ноду **`Director`**, тянет в неё провод от компонентов
   (`artifact`) и от страницы (`ir`).
3. В ноде пишет бриф в одну строку: *«30-секундный ролик для лендинга: показать,
   как создаётся счёт за один клик»*. Выбирает пресет (`Промо 16:9`,
   `Реклама 9:16`, `Онбординг`) и провайдера — **OpenAI / Codex CLI / Claude CLI**
   (тот же `NodeProvider`, что уже во всех AI-нодах).
4. Жмёт «Собрать ролик». ИИ раскладывает бриф на сцены, для каждой выбирает
   **что показать** (конкретный наш компонент) и **каким приёмом** (из каталога
   приёмов), расставляет ритм и акценты.
5. Провод `storyboard` идёт в ноду **`Motion`** → там таймлайн. Пользователь
   двигает границы сцен, меняет приём в выпадающем списке, таскает рамку камеры
   прямо по превью, отключает лишнее, добавляет свою сцену.
6. «Рендер» → mp4. Существующий пайплайн `motion_render.py`.

Никакого монтажа, никакого After Effects. Но выглядеть должно так, будто он был.

---

## 2. Главное архитектурное решение

**ИИ не пишет анимацию. ИИ выбирает приёмы и цели.**

Три слоя, жёстко разделённые:

| Слой | Кто делает | Артефакт |
|---|---|---|
| **ЧТО показываем** | уже есть в системе | Design IR / Source Artifact — реальные компоненты, состояния, токены |
| **КАК показываем** | детерминированный код | **Каталог приёмов** (Shot Library) — библиотека motion-приёмов с выверенными кривыми |
| **ЧТО чем и в каком порядке** | ИИ | **Storyboard IR** — список сцен: цель + приём + длительность |

Почему так. Если дать модели писать keyframes напрямую — получится дёрганое
месиво: модель не чувствует ритм, ставит линейные кривые, промахивается по
таймингам. Если дать ей выбирать из каталога, где каждый приём уже сделан
руками дизайнера с правильными `spring`/`bezier`, стаггером и таймингом, —
результат выглядит профессионально **независимо от того, насколько хороша
модель**. Модель отвечает за смысл, каталог — за красоту.

Это тот же принцип, что уже принят в репозитории: LLM предлагает,
детерминированный код проверяет и исполняет (см. `app/fidelity_repair.py`).

```
Source Artifact ─┐
Design IR ───────┼─► Director (ИИ) ──storyboard──► Компилятор ──► Motion IR ──► Таймлайн ──► mp4
Бриф (текст) ────┤     выбирает        (что+приём)   (детерм.)      (правится руками)
Design System ───┘     приёмы                        ↑
                                              Каталог приёмов
```

## 3. Каталог приёмов — сердце качества

`app/motion/shots/` — по модулю на приём, плюс реестр `app/motion/shots/registry.py`.
Данные приёма (тайминги, кривые, стаггер) лежат в JSON рядом, чтобы дизайнер мог
крутить их без кода.

Каждый приём — чистая функция:

```python
def build(target: Target, ctx: ShotContext) -> list[LayerPatch]:
    """Вернуть слои и property-треки Motion IR для одной сцены."""
```

`ctx` даёт: длительность сцены, композицию, токены Design System (цвет акцента,
радиусы, тени), viewport, предыдущий и следующий приём (для стыковки).

### Стартовый набор (v1) — 14 приёмов

**Кадр и камера**
| Приём | Что делает |
|---|---|
| `establish` | Полная страница в кадре, лёгкий медленный zoom-in (1.0 → 1.04) — «вот сайт» |
| `zoom-to-region` | Наезд на область компонента с параллаксом фона, `bezier` ease-out, хвост-hold |
| `pan-scroll` | Имитация прокрутки страницы: камера едет по вертикали с инерцией и оверскроллом на концах |
| `orbit-card` | Лёгкий 3D-наклон карточки при въезде (rotation + scale), как в промо Apple |

**Реальное взаимодействие (скринкаст)**
| Приём | Что делает |
|---|---|
| `cursor-click` | Курсор приезжает `spring`-траекторией к элементу, замирает, клик + ripple, элемент переходит в состояние `active` |
| `cursor-hover` | Курсор наводится, компонент переключается в наблюдённое состояние `hover` (у нас оно измерено в Source Artifact) |
| `type-into` | Печать в поле по символам с реалистичным джиттером интервалов + мигающий каретка |
| `state-swap` | Компонент меняет состояние (`default → loading → success`) с кроссфейдом и подскоком |

**Акцент и объяснение**
| Приём | Что делает |
|---|---|
| `spotlight` | Всё, кроме таргета, уходит в затемнение + blur; таргет чуть приподнимается тенью |
| `callout` | Линия-выноска с подписью, рисуется по `mask.path`; стиль — из токенов Design System |
| `stagger-reveal` | Дети контейнера (пункты списка, карточки сетки) появляются каскадом, шаг 60–90 мс, `spring` |
| `number-count` | Число в компоненте докручивается от 0 до значения с ease-out |

**Начало и конец**
| Приём | Что делает |
|---|---|
| `title-card` | Титр на фоне из бренд-градиента, типографика из Design System |
| `cta-outro` | Финальный кадр: логотип + кнопка + текст, всё собирается стаггером |

Каждый приём обязан:
- строить keyframes **только** через разрешённые `propertyPath` Motion IR
  (`transform.*`, `opacity`, `crop`, `blur`, `mask.*`);
- брать цвета/радиусы/шрифты **только** из токенов Design System, не хардкодить;
- уметь ужаться и растянуться в диапазоне `[minDuration, maxDuration]` без
  ломки кривых;
- иметь превью-гифку 2 с для UI выбора приёма (генерится тестом, лежит в
  `app/static/shots/`).

### Ритм — тоже код, не модель

`app/motion/rhythm.py`. После того как ИИ вернул порядок сцен, детерминированный
проход правит тайминги:

- длительность сцены = базовая для приёма × коэффициент пресета × вес важности;
- сумма подгоняется под целевой хронометраж пресета;
- соседние однотипные приёмы разводятся (два `zoom-to-region` подряд → второй
  заменяется на `pan-scroll` или между ними вставляется `cut`);
- переход между сценами выбирается по паре приёмов таблицей, а не моделью
  (`establish → zoom-to-region` = `cut`; `spotlight → spotlight` = `fade 200мс`);
- микро-пауза 120–200 мс перед каждым акцентом — то, что делает ролик «дышащим».

Это ровно то, что отличает «слайд-шоу» от «сделано в After Effects».

## 4. Storyboard IR — то, что пишет ИИ

`schema/storyboard-ir-1.0.schema.json`, модуль `app/ir/storyboard.py`.
Единственный артефакт от модели. Намеренно маленький и тупой — чем меньше
свободы, тем стабильнее результат.

```jsonc
{
  "version": "1.0",
  "source": { "baseDesignIrHash": "…", "sourceArtifactHash": "…" },
  "brief": "30-секундный ролик для лендинга: счёт за один клик",
  "format": "promo-16x9",
  "scenes": [
    {
      "id": "sc-01",
      "shot": "establish",
      "target": null,
      "weight": 1.0,
      "note": "открываем сайт",
      "text": null
    },
    {
      "id": "sc-02",
      "shot": "zoom-to-region",
      "target": { "kind": "component", "ref": "cmp_invoice_table" },
      "weight": 1.4,
      "note": "вот где живут счета",
      "text": null
    },
    {
      "id": "sc-03",
      "shot": "cursor-click",
      "target": { "kind": "sourceKey", "ref": "src:btn.primary#3" },
      "weight": 1.2,
      "note": "один клик — счёт создан",
      "text": null
    },
    {
      "id": "sc-04",
      "shot": "state-swap",
      "target": { "kind": "component", "ref": "cmp_invoice_row" },
      "weight": 1.0,
      "note": "строка появилась",
      "text": null
    },
    {
      "id": "sc-05",
      "shot": "cta-outro",
      "target": null,
      "weight": 0.8,
      "note": "финал",
      "text": "Счета за 5 секунд. Попробуйте бесплатно."
    }
  ]
}
```

Модель **не задаёт** длительности, кривые, переходы, координаты. Только: приём,
цель, относительный вес, подпись. Всё остальное — `rhythm.py` и каталог.

### Инварианты (валидация до компиляции, `app/ir/storyboard.py:validate`)

- `shot` есть в реестре приёмов — иначе ошибка;
- `target.ref` **существует** в Design IR / Source Artifact — несуществующая
  ссылка это ошибка 422, а не «нарисуем что-нибудь». Это главная точка, где
  обычно ломается «модель придумала экран»;
- приём совместим с типом цели (`type-into` только на поле ввода, `number-count`
  только на текст с числом, `stagger-reveal` только на контейнер с ≥2 детьми) —
  таблица совместимости в `registry.py`;
- `cursor-*` требует, чтобы у компонента было наблюдённое состояние
  (`SourceArtifactComponent.states`), иначе приём деградирует до `spotlight`;
- количество сцен в диапазоне пресета;
- первая сцена — из группы «начало», последняя — из группы «конец» (для пресетов,
  где это задано).

Ошибка инварианта → одна автоматическая переспроска модели с текстом ошибки
(как в существующем конверте `app/llm_client.py`), потом отказ с понятным
сообщением в ноде.

## 6. Компилятор

`app/motion/compile.py`

```
compile_storyboard(storyboard, base_ir, source_artifact, tokens, preset) -> (motion_ir, scene_irs)
```

Порядок:

1. валидация Storyboard IR (п. 4);
2. `rhythm.py` расставляет `start`/`duration`/переходы;
3. для каждой сцены вызывается `build()` её приёма → слои и property-треки;
4. сборка композиции: фон, опциональная рамка браузера, слой курсора,
   `markers[]` по сценам;
5. `validate_motion_v21` — fail-closed. Любая ошибка = 422, не «починим на рендере».

**LLM внутри компилятора не вызывается.** Один и тот же Storyboard всегда даёт
побитово одинаковый Motion IR (проверяется тестом через `content_hash`).

### Motion IR 2.1 — аддитивное расширение 2.0

Схема 2.0 закрыта (`additionalProperties: false`), поэтому нужна версия.
Миграция fail-closed по образцу `migrate_motion_v1_to_v2` в `app/ir/motion_v2.py`.

Добавляем (всё опционально, все 2.0-документы остаются валидны):

- `layer.shotId` — какой сценой раскадровки порождён слой (нужно для правки и
  перекомпиляции);
- `layer.detached: boolean` — слой правили руками, перекомпиляция его не трогает;
- `composition.safeAreas: [{ id, role, rect }]` — место под говорящую голову /
  субтитры, если пользователь пишет видео поверх;
- `marker.kind: "scene" | "accent"`;
- `source.storyboardHash`.

## 7. Ноды и порты

### 7.1 Новый kind

`frontend/src/flow/types.ts`:

```ts
export type PortKind = "text" | "ir" | "tokens" | "artifact" | "interaction" | "motion"
                     | "storyboard";
```

### 7.2 Нода `director` — «Режиссёр»

`frontend/src/nodes/DirectorNode.svelte`

- **Входы:** `ir` (Design IR страницы), `artifact` (Source Artifact),
  `tokens` (Design System), `text` (бриф проводом из ноды Промпт — опционально),
  `interaction` (реальная запись из Recorder — опционально, тогда ИИ обязан
  следовать записанным шагам).
- **Выход:** `storyboard`.
- **Данные:**
  ```ts
  type DirectorNodeData = {
    brief: string;
    preset: "promo-16x9" | "ad-9x16" | "ad-1x1" | "onboarding-16x9" | "feature-loop";
    provider: NodeProvider;          // "openai" | "codex" | "claude" — как везде
    effort: "medium" | "high" | "max";
    storyboard: IRObject | null;
    ir: IRObject | null;
    artifact: SourceArtifact | null;
    interaction: InteractionObject | null;
    log: string[];
    lastError?: string;
  };
  ```
- **UI ноды:** поле брифа, селект пресета, `ProviderPicker` (уже есть компонент),
  кнопка «Собрать ролик», под ней — горизонтальная лента сцен: миниатюра цели +
  иконка приёма + длительность. Клик по сцене — подсветка цели на превью.

### 7.3 Нода `motion` — расширяем, не ломаем

Добавляется вход `storyboard`. Разрешение источника:

- есть `storyboard` → компилируем через `/api/motion/compile` (Motion IR 2.1);
- нет `storyboard`, есть `interaction` → текущее поведение `build_motion` (1.0).

Существующие графы работают как раньше. `MotionNodeData` дополняется:

```ts
storyboard: IRObject | null;
version: "1.0" | "2.1";
detachedScenes: string[];        // сцены, правленные руками
```

`frontend/src/flow/ports.ts`:

- `PORTS.director`, `PORTS.motion.in += storyboard`;

## 8. Ручное редактирование в ноде Motion

Это половина ценности — без неё ИИ-ролик остаётся лотереей.

### 8.1 Что правится и на каком уровне

| Правка | Уровень | Что происходит |
|---|---|---|
| Границы сцены (драг на таймлайне) | Storyboard | меняется `duration`, перекомпиляция сцены |
| Смена приёма (выпадающий список с превью-гифками) | Storyboard | перекомпиляция сцены |
| Смена цели (клик по компоненту на превью) | Storyboard | перекомпиляция сцены |
| Порядок сцен (драг блока) | Storyboard | пересчёт `rhythm`, перекомпиляция |
| Отключить / удалить / дублировать сцену | Storyboard | перекомпиляция |
| Добавить сцену вручную | Storyboard | выбор приёма + цели из списка |
| Рамка камеры (тянуть прямо по превью) | Storyboard | параметр приёма, перекомпиляция |
| Переход и его длительность | Storyboard | перекомпиляция |
| Keyframes слоя (продвинутый режим) | **Motion IR** | слой помечается `detached: true` |
| Текст титра / CTA | Storyboard | перекомпиляция |

**Правило:** Storyboard — источник правды. Motion IR производный. Ручная правка
keyframes ставит слою `detached: true`, и перекомпиляция его не перезаписывает,
а в UI появляется бейдж «правлено вручную» с кнопкой «вернуть к приёму».
Без этого правила следующая перекомпиляция молча затрёт ручную работу.

### 8.2 Таймлайн — что видно

Три синхронные дорожки под превью:

1. **Сцены** — блоки, цвет по группе приёма, внутри иконка приёма и миниатюра
   цели. Границы тянутся. Это то, что пользователь трогает в 90% случаев.
2. **Акценты** — маркеры `kind: "accent"`: клики, появления, счётчики. Показывают
   ритм ролика одним взглядом.
3. **Слои** — скомпилированные слои Motion IR. Свёрнуты по умолчанию,
   разворачиваются для правки keyframes. `detached`-слои помечены.

Плейхед общий, `rAF`-цикл уже реализован в `MotionWorkspace.svelte:60`.
Undo/redo — через существующий `frontend/src/engine/irhistory.ts`.

### 8.3 Инспектор сцены (панель справа)

Выбрана сцена → приём (селект с превью), цель (с миниатюрой и кнопкой «выбрать
на превью»), длительность, вес, переход, параметры приёма (для `zoom-to-region` —
рамка; для `type-into` — текст и скорость; для `callout` — подпись и сторона),
заметка режиссёра, кнопка «Перегенерировать эту сцену» (одиночный вызов ИИ
только на неё).

## 9. Автопроверка качества

`app/motion/judge.py` — детерминированный. Рендерит кадры в середине каждой сцены
и на границах переходов существующим `motion_render.py`, проверяет:

| Проверка | Порог |
|---|---|
| Цель сцены видна в кадре | ≥ 60% своей площади |
| Текст не обрезан и не наезжает на край | клиппинг = 0, отступ ≥ 24 px |
| Контраст титров и выносок | ≥ 4.5:1 (`app/colorutils.py`) |
| Сцена не короче минимума приёма | 0 нарушений |
| Нет двух одинаковых приёмов подряд | 0 |
| Нет статичного кадра дольше 3 с | 0 |
| Кадр не пустой (что-то в фокусе) | покрытие ≥ 15% |

Находки показываются булавками на дорожке сцен: кадр, метрика, порог, факт.
Кнопка «Починить» правит **Storyboard** (модель меняет приём/цель/вес),
компиляция и замер повторяются, **правка принимается только при росте балла** —
тот же контракт, что в `app/fidelity_repair.py`. Максимум 3 итерации, всё в лог.

## 11. Промпт режиссёра

`app/prompts/DIRECTOR.md` — рядом с существующими `BLOCKS.md` и `DESIGN.md`.

В контекст подаётся:
- бриф пользователя;
- пресет с ограничениями (хронометраж, число сцен, обязательные группы);
- **инвентарь целей**: список компонентов из Source Artifact с `name`, `role`,
  наблюдёнными состояниями и превью (в `SourceArtifactComponent` это всё уже есть);
- **каталог приёмов** с описанием, требованиями к цели и примером применения;
- токены Design System (чтобы модель понимала характер бренда — строгий/игривый);
- если подключён Interaction IR — записанная последовательность шагов, которой
  надо следовать.

Ответ — **только Storyboard IR** через существующий конверт со схемой
(`app/llm_client.py`). Провайдер — `openai`, `codex` или `claude`, как во всех
AI-нодах; Codex и Claude идут через локальный CLI по подписке.

## 12. Этапы

| Этап | Содержание | Флаг | Готово, когда |
|---|---|---|---|
| 1 | Каталог приёмов: 6 базовых (`establish`, `zoom-to-region`, `spotlight`, `stagger-reveal`, `title-card`, `cta-outro`), реестр, превью | off | Каждый приём рендерится в 2-секундный ролик и выглядит хорошо на глаз |
| 2 | Storyboard IR + валидатор + `rhythm.py` + компилятор + Motion IR 2.1 | off | Рукописный storyboard → mp4 существующим рендером |
| 3 | Нода `director`, промпт, `/api/director/storyboard` | **on** | На реальном Source Artifact бриф → раскадровка без несуществующих целей |
| 4 | Таймлайн: дорожка сцен, смена приёма, драг границ, инспектор сцены | on | Ролик правится руками без перегенерации |
| 5 | Остальные 8 приёмов (курсор, печать, состояния, выноски, счётчик, скролл, orbit, hover) | on | Ролик неотличим от скринкаста |
| 6 | Judge + repair | on | Балл растёт на всех фикстурах, откат при падении работает |

Этапы 1–2 полностью детерминированные и делаются **без единого вызова LLM**.
Это сознательно: сначала научиться делать красиво по рукописной раскадровке,
потом подключать модель. Обратный порядок гарантированно даёт «ИИ сделал кашу,
и непонятно, кто виноват».

## 13. Приёмка

Сквозной сценарий:

1. `Source Import` реального сайта → Source Artifact с ≥ 8 компонентами.
2. `Director`: бриф «30-секундный промо-ролик, показать создание счёта в один
   клик», пресет `promo-16x9`, провайдер Claude CLI.
3. Раскадровка: 6–8 сцен, каждая цель существует, приёмы не повторяются подряд,
   первая — `establish`, последняя — `cta-outro`.
4. `Motion`: компиляция → Motion IR 2.1, сумма длительностей 20–40 с.
5. Правка руками: сменить приём в сцене 3, растянуть сцену 5, подвинуть рамку
   камеры в сцене 2 — всё применяется без перегенерации остального.
6. Judge → 0 находок либо починка их закрывает.
7. Рендер → mp4 1920×1080, воспроизводится, плавно, без рывков на переходах.

Тесты (конвенция репозитория — рядом с модулем, суффикс `_test.py`):

- `app/motion/shots/registry_test.py` — каждый приём строит валидные треки на
  синтетической цели, ужимается и растягивается в своём диапазоне;
- `app/ir/storyboard_test.py` — каждый инвариант п. 4 отдельным кейсом;
- `app/motion/rhythm_test.py` — сумма попадает в хронометраж, дубли разведены;
- `app/motion/compile_test.py` — детерминизм: один вход → один `content_hash`;
- `app/ir/motion_v2_test.py` — дополнить миграцией 2.0 → 2.1;
- `app/motion/judge_test.py` — синтетические кадры с известными нарушениями;
- `app/motion_director_live_test.py` — live-тест по образцу
  `app/fidelity_repair_live_test.py`, требует провайдера.

## 14. Что осознанно не делаем в v1

- **Звук и озвучка.** `motion_render.py` собирает поток с `-an`. Ролик выходит
  немой — под музыку и голос он кладётся снаружи. Синхронизация анимации с
  дикторским текстом по SRT — отдельная задача после этапа 6; Motion IR 2.0 уже
  содержит `captions[]` и `assets[type: "audio"]`, контейнер под неё готов.
- **Съёмка говорящей головы.** Только `safeAreas` в композиции, чтобы контент
  не залезал в зарезервированное место.
- **Произвольные видео/картинки со стороны.** Только наши компоненты.
- **3D, частицы, морфинг.** Каталог приёмов расширяемый, но не в v1.

## 15. Вопросы, требующие решения

1. **Рамка браузера.** Рисуем ли поддельный browser chrome вокруг страницы
   (сильно усиливает ощущение «скринкаст»)? Предлагаю да, как опция пресета,
   с тремя стилями — macOS, Windows, безрамочный.
2. **Скорость каталога.** 14 приёмов — это ≈ 2 недели дизайнерской работы на
   доводку кривых. Начинаем с 6 (этап 1) и растём, или ждём полный набор?
   Предлагаю первое.
3. **Ограничение по кадрам.** `MAX_RENDER_FRAMES = 10_800` (`app/motion_render.py:15`)
   = 6 минут при 30 fps. Для `onboarding-16x9` до 180 с этого хватает, но при
   60 fps — впритык. Поднимаем лимит или фиксируем 30 fps для длинных пресетов?
