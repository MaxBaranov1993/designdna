# Ноды и редакторы: проверка и исправления

Проверенная база: `codex/astra-model-and-audit`, после добавления выбора GPT Sol / Astra / Claude. Изменения предназначены для PR #2 в `codex/unified-motion-design`.

## План и результат

1. Составить карту 17 типов: реестр, динамические порты, диспетчер запуска, сохранение и загрузка — выполнено.
2. Проверить связи, разветвления, удаление и восстановление графа — добавлены исполняемые регрессии, ошибки исправлены.
3. Проверить DNA Editor: ручные правки, ревизии, история, повторное подключение источника — исправлены подтверждённые ошибки состояния.
4. Проверить Video Editor и Motion Editor: ключи, тайминг, история, сохранение, маршрут экспорта — исправлены ошибки; визуальное соответствие кадров требует отдельного браузерного прогона.
5. Собрать приложение, прогнать доступные проверки и обновить PR — результаты ниже.

## Исправленные ошибки

### Граф и DNA Editor

- Удаление связи/источника обновляет получателей. Canvas больше не возвращает устаревшие `data` поверх уже обновлённого стора.
- Разветвления читают актуальное состояние каждой ветки; общий потомок получает изменения обеих ветвей.
- DNA-нода запоминает маркер входной композиции. Неизменившийся источник не заменяет сохранённые ручные правки и не создаёт ложный конфликт ревизии. Маркер переживает перезагрузку проекта.
- Удаление входа DNA-ноды можно отменить вместе с его связью.
- Отказ операции, например над заблокированным слоем, не уничтожает ранее доступный Redo. Горячие клавиши Undo/Redo не вмешиваются в активное AI-превью.
- Загрузка старых частичных нод восстанавливает вложенные настройки. Повторяющиеся ID отклоняются; некорректные порты, циклы и лишние провода одного входа отбрасываются с уведомлением.
- API показывает текст ошибки сервера из `error`, а не только HTTP-код. Ошибка загрузки редактора отображается пользователю.

### Video Editor

- Появился числовой ввод значений ключей; opacity и scale ограничены допустимыми значениями.
- Перемещение ключа не создаёт одинаковые временные позиции и корректно продолжает жест после округления по кадрам.
- Уменьшение длительности обрезает треки с вычислением значения на границе; ключи за пределами композиции не ломают валидацию. Полноразмерный клип растёт при увеличении длительности.
- Добавлены Redo и горячие клавиши; жесты объединяются в одно действие, действия без изменения не засоряют историю.
- Каждый коммит проверяет текущий документ и ревизию входа, обновляет параметры ноды и выход графа, сбрасывает прежнее видео. Запоздавшая сборка не восстанавливает устаревший вход.
- Закрытие ждёт сохранения. При ошибке редактор остаётся открытым; черновик можно скачать или явно закрыть без последних правок.
- ИИ-режиссёр получает выбранные GPT Sol / Astra / Codex / Claude и effort. Детерминированный режим и fallback остаются видимыми в превью.
- Скачивание видео в desktop использует файловый мост.

### Motion Editor и видеоартефакты

- Раньше видеоэкспорт игнорировал редактируемые слои. Теперь в запрос и worker передаются их текст/изображения и ключи.
- Превью и экспорт используют общий расчёт слоёв и переходов. Настройки длительности/переходов учитываются в композиции; перед экспортом Motion IR пересобирается с текущими настройками кадра и качества.
- Добавлена история правок слоёв. Пустой список после удаления последнего слоя больше не восстанавливает дефолтные слои самопроизвольно.
- Локальные `ddna://blobs` изображения материализуются до постановки рендера в очередь. Неисправные слои/ключи/ассеты отклоняются до дорогого рендера.
- Завершённые видео сохраняются в проекте. Незавершённые runtime-задачи не загружаются как вечный busy. Timeline API умеет найти завершённый файл после перезапуска worker.
- Изменение содержимого или настроек рендера снимает прежний готовый видеоартефакт с выхода.

## Проверки

Финальный результат: **35/35 frontend-тестов**, включая **26 внутренних engine-проверок**; **78/78 серверных тестов**; production build успешен, **0 ошибок и 0 предупреждений Svelte/TypeScript**. Тесты используют фикстуры и подмену внешнего ответа там, где речь идёт о моделях/очереди рендера; это не реальные платные запросы и не проверка кодека.

- `node --test frontend/tests/*.test.mjs` — общий набор frontend, включая новые регрессии контрактов и 26 внутренних engine-проверок.
- `npm --prefix frontend run build` — TypeScript/Svelte и обе production-сборки, включая headless `engine.js`.
- `python -m pytest app/motion_composition_test.py app/timeline_ir_test.py app/timeline_api_test.py app/timeline_director_test.py app/timeline_guard_test.py app/editor_assist_test.py app/model_selection_test.py -q` — серверный набор этого прохода.

Пять ранее падавших проверок исходного текста обновлены под актуальные контракты: измеряемый прогресс, новый порт `designSystem`, текущая гидратация и русская подпись защиты точных мастеров. Исполняемые проверки графа добавлены отдельно.

## Оставшиеся ограничения и следующий приоритет

1. Облачный браузер блокирует локальное превью; в окружении также нет установленного Chromium для кадровых регрессий. Не подтверждены клики/drag на реальной странице, поведение фокуса, пиксельное совпадение превью и MP4/WebM, Electron smoke. Существующие `app/ui_editor_*`, `app/ui_motion_editor_test.py`, `app/ui_timeline_workspace_test.py`, `app/motion_render_test.py` нужно прогнать на машине с браузером. Изменённая семантика no-op истории потребует актуализации старых UI-сценариев, рассчитывающих на лишние Undo-шаги.
2. Motion и Timeline всё ещё имеют разные документы и UI. Общий расчёт Motion-экспорта исправляет потерю слоёв, но не завершает миграцию на единую модель композиции.
3. `comp`-слой Motion по-прежнему представляет карточку с названием, а не живой мастер Design System. Следующий продуктовый шаг — реальная вставка мастер-IR с устойчивой ссылкой на ревизию.
4. Очередь рендера остаётся в памяти. Завершённые файлы восстанавливаются, но надёжное возобновление активной задачи между страницами и перезапусками требует постоянного реестра задач, отмены и повторного подключения к прогрессу.
5. Состояния run-based нод стоит унифицировать: «нет входа / готово / вход изменился / выполняется / ошибка». Сейчас ноды показывают статус, но отдельной общей модели устаревания результатов нет.
6. После визуального smoke: выровнять язык и подписи двух редакторов, проверить узкие окна и клавиатурный фокус; затем измерить время до первого результата и понятность стартовых цепочек на новых пользователях.

Этот проход устраняет воспроизведённые ошибки и расширяет проверку. Он не даёт гарантии отсутствия всех ошибок во всех окружениях.
