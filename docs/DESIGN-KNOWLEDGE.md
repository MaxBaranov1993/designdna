# DesignAI Web — База знаний по веб-дизайну

Документ для генератора и промпт-инжиниринга. Правила, паттерны и принципы,
собраные из открытых источников лучших студий и дизайн-систем.

---

## 1. Главный принцип: редактор, а не генератор

**Когда есть референс (скриншот, описание, URL) — режим EDIT:**
- Воспроизвести структуру ТОЧНО: те же секции, те же элементы, тот же порядок.
- Воспроизвести контент ТОЧНО: те же тексты, те же кнопки, те же изображения.
- Применить ТОЛЬКО запрошенное изменение. Ничего больше.
- НЕ добавлять секции/блоки/элементы, которых нет в референсе.
- НЕ убирать элементы из референса.
- НЕ «улучшать» дизайн — если референс простой, результат простой.

**Когда референса нет — режим GENERATE:**
- Свободное творчество в рамках брифа.
- Следовать правилам качества ниже.

## 2. Правила интерпретации референсов

### 2.1 Что извлекать из скриншота/описания

При анализе референса (вручную или через vision-модель) фиксировать:

| Параметр | Что записывать |
|---|---|
| **Структура** | Список секций сверху вниз: navbar, hero, grid, footer… |
| **Контент** | Точные тексты заголовков, кнопок, описаний |
| **Раскладка** | Колонки, сетка, выравнивание, пропорции |
| **Палитра** | Доминантный цвет, акцент, фон, текст (hex) |
| **Типографика** | Семейство, начертание, иерархия размеров |
| **Компоненты** | Типы карточек, кнопок, инпутов, бейджей |
| **Настроение** | minimal / bold / playful / corporate / dark / glass |

### 2.2 Как применять модификацию

- «Поменяй цвета кнопок на оранжевый» → меняешь ТОЛЬКО `tokens.color.primary`
  (или variant кнопок). Структура, тексты, раскладка — без изменений.
- «Перемести sidebar вправо» → меняешь порядок/позицию ОДНОГО блока.
  Остальное — verbatim.
- «Сделай как на скриншоте, но тёмная тема» → воспроизводишь структуру,
  инвертируешь токены на dark mode.

### 2.3 Чего НЕ делать

- Не добавлять hero, если на скриншоте только шапка.
- Не добавлять footer, если его нет в референсе.
- Не заменять текст на «более красивый» — использовать оригинальный.
- Не менять количество карточек/элементов в сетке.
- Не добавлять анимации/эффекты, которых нет в референсе.

## 3. Паттерны компонентов (из лучших практик)

Источники: Stripe (stripe.com), Linear (linear.app), Vercel (vercel.com),
Apple HIG, Material Design 3, Tailwind UI, shadcn/ui, Untitled UI.

### 3.1 Navbar / шапка

- **classic**: лого слева, ссылки по центру/справа, CTA-кнопка справа.
- **centered**: лого по центру, ссылки симметрично по бокам.
- **minimal**: лого + ссылки, без CTA.
- Высота: 56–72px. Sticky по умолчанию. Фон: прозрачный или surface.
- Ссылки: 3–6 штук, font-size 14px, muted color, hover → text color.

### 3.2 Hero

- **centered**: заголовок + подзаголовок + CTA по центру.
- **split**: текст слева, медиа справа (или наоборот).
- Заголовок: 1–2 строки, ≤12 слов, display font, 40–56px.
- Подзаголовок: 1–3 строки, body font, 16–18px, muted.
- CTA: primary + secondary (outline/ghost).

### 3.3 Карточки (card)

- Фон: surface, border: 1px border-color, radius: card token.
- Padding: 20–24px. Shadow: sm или md.
- Структура: icon/badge → title → text → action.

### 3.4 Pricing

- 2–4 тарифа в ряд. Highlighted — акцентный border + badge «Популярный».
- Структура: name → price → features list → CTA button.

### 3.5 Карта / map-компонент

- Контейнер с aspect-ratio 16:9 или 4:3.
- Внутри: imagePrompt с описанием карты (пины, маркеры, стиль).
- Sidebar/overlay: список точек с названием, адресом, рейтингом.
- НЕ добавлять секции вокруг карты, если референс — только карта.

### 3.6 Footer

- **simple**: лого + copyright в одну строку.
- **columns**: лого + tagline слева, 2–4 колонки ссылок справа.
- Фон: surface или background, border-top.

## 4. Правила качества (Design Quality Bar)

### 4.1 Типографика

- Максимум 2 семейства: display (заголовки) + body (текст).
- Иерархия: hero heading > section heading > card title > body > caption.
- Line-height: 1.1–1.2 для заголовков, 1.5–1.7 для body.
- Letter-spacing: -0.02em для крупных заголовков, 0 для body.

### 4.2 Цвет

- Один доминантный (primary), один акцент (accent), нейтральные (bg/surface/text/border).
- Контраст текст/фон ≥ 4.5:1 (WCAG AA).
- Не более 5 цветов в палитре (не считая нейтральных).
- Тёмная тема: не просто инверсия — фон #0E0E12–#1A1A2E, surface на 1–2 ступени светлее.

### 4.3 Отступы и сетка

- Section padding: 64–96px вертикально (desktop).
- Container max-width: 880–1120px, margin auto.
- Gap между карточками: 16–24px.
- Внутренний padding карточек: 20–24px.

### 4.4 Радиусы

- Консистентность: один пресет на весь дизайн (sm/md/lg/full).
- Карточки и инпуты — один радиус, кнопки — тот же или на ступень меньше.

### 4.5 Тени

- sm: карточки в потоке. md: hover/elevated. lg: модалки/dropdown.
- Не использовать тени на тёмном фоне — лучше border + subtle glow.

## 5. Промпт-инжиниринг: как формулировать задачи

### 5.1 Для генерации (без референса)

Хороший бриф содержит:
1. **Тип продукта** (SaaS, маркетплейс, лендинг, дашборд).
2. **Целевая аудитория** (CMO, разработчики, потребители).
3. **Настроение/стиль** (minimal, bold, playful, corporate).
4. **Ключевые секции** (hero, features, pricing, faq).
5. **Язык контента** (русский, английский).

Пример: «Лендинг SaaS-платформы аналитики для CMO. Стиль: minimal, светлая тема,
много воздуха. Секции: hero с дашбордом, feature-grid 3×2, pricing 3 тарифа,
faq аккордеон, footer columns.»

### 5.2 Для редактирования (с референсом)

Хорошая инструкция:
1. **Что менять** (цвета, текст, позицию, размер).
2. **На что менять** (конкретное значение).
3. **Что НЕ трогать** (неявно: всё остальное).

Пример: «Поменяй цвет primary на #E85D26. Остальное не трогай.»
Пример: «Перемести блок sidebar вправо от карты. Структуру не меняй.»

### 5.3 Для клона (с URL)

1. **URL** страницы.
2. **Какой компонент** клонировать (шапка, карточка, sidebar, footer).
3. **Точность**: «точь-в-точь» = воспроизвести HTML/CSS структуру как IR.

## 7. Частые ошибки генерации (и как их избежать)

| Ошибка | Причина | Решение |
|---|---|---|
| Лишние секции | Модель «дорисовывает» лендинг | Режим edit: строго по референсу |
| Другой текст | Модель «улучшает» копирайтинг | Режим edit: verbatim из референса |
| Неправильная палитра | Модель игнорирует styleHint | Явно перечислять hex в styleHint |
| Generic placeholder | Модель не понимает контекст | Vision-анализ скриншота → структурированное описание |
| Несовпадение структуры | Модель выбирает свой variant | Указывать variant явно в промпте |
| Мобильная раскладка на desktop | Модель не знает ширину | Указывать artboard width в frame |

## 8. Правила для vision-анализа скриншотов

При разборе скриншота (qwen-vl / Kimi vision) извлекать:

```json
{
  "layout": "описание раскладки сверху вниз",
  "sections": ["navbar", "hero-split", "feature-grid-3", "footer-columns"],
  "colors": { "primary": "#...", "background": "#...", "text": "#..." },
  "typography": { "heading": "sans-serif bold 48px", "body": "sans-serif 16px" },
  "components": ["card с иконкой", "button primary", "badge"],
  "content": { "heading": "точный текст", "cta": "точный текст кнопки" },
  "mood": "minimal | bold | playful | corporate | dark",
  "spacing": "compact | default | spacious"
}
```

Это структурированное описание подставляется в `{{STYLE_HINT}}` системного промпта,
давая модели точный контекст вместо свободного текста пользователя.
